# ADR：行内 marks 行级化（O-11 / C-30 / R-2）

状态：**已接受原则（Accepted-in-principle）· 分阶段推迟实施**
日期：2026-10-22
关联：`docs/qa/deviation-analysis.md` C-30 / R-2、`docs/qa/optimization-plan.md` O-11

## 1. 背景与问题

当前 IR 的格式粒度是**块级布尔**（`Block.marks: {bold, italic, strikethrough}`），
只在「所有非空来源行都统一带格式」时写入（CH-483 R8-PIPE-7 的 AND 语义，
CH-485 R9-PIPE-5 加了「续行只清不置」防扩散）。S4 渲染即整块包裹：

- 段落内**局部**加粗/斜体/删除线（技术文档最常见形态：`使用 **--force** 前
  先确认`）→ 任何一方不统一 → 整块零 marks → 行内强调全部丢失；
- 混合格式段落若被误判统一，会把局部强调**扩散**成整段（AND 语义已把该面
  压到极小，但代价是几乎永远不命中）。

这是「宁漏勿误」在格式维度上的保守站位：丢失强调不改变语义正确性（对照
C-04 折行空格那种**语义损伤**），但技术文档保真度显著受限（C-30 / R-2 的
用户面结论）。

## 2. 决策

**接受 span 模型为演进方向，但不在本轮实施。** 理由（与既有纪律的对谈）：

1. **与 G6 的冲突是本轮最大的量级问题。** span 模型要求 SCHEMA_VERSION
   14→15、`blocks` 表迁移、S1/S3/S4 三层贯通、全语料（含 6 黄金样本 sha
   绑定）重烤。当前 O-01~O-10 刚完成一轮全量重烤，紧跟着再来一次会把两轮
   变更压进同一份基线——出问题时无法归因。
2. **「宁漏勿误」没有被违反，只是有代价。** 丢强调 = 保序不保形；引入
   span 后若渲染越界/重叠处理不当 = 制造**破损 Markdown**（如 `**a *b** c*`），
   那才是违反纪律。span 渲染的边界正确性需要独立的红线层，不能搭车。
3. **证据面已具备，实施不需要重做 S1。** DOCX run 级：`_docx_para_line`
   已逐 run 遍历（uniform_* 判定处），run 起止偏移在装配 text 时可同步记录；
   PDF char 级：`Line.chars`（pdfplumber 字符数组）自带每字符格式。证据
   采集是**增量**工作，不是障碍。

### 触发条件（满足其一即启动阶段 1）

- T1：真实用户语料中出现「行内格式丢失导致实质信息损失」的案例登记
  （如同 C-04 之于折行空格——需要真实痛点驱动，不为指标优化）；
- T2：任一必然 bump `SCHEMA_VERSION` 的变更立项（搭车实施，边际重烤成本 ≈ 0）；
- T3：编辑面（`edits.py`）需要字符级定位的特性的先行落地（span 坐标系
  是它的前置依赖）。

## 3. 方案骨架（阶段 1 实施时按此展开）

### 3.1 IR 契约

```
Block.spans: list[dict] | None      # None = 无行内格式（缺省，零字节影响）
# span: {"start": int, "end": int, "marks": {"bold": True, ...}}
# 坐标系：Block.text 的 Unicode 码点偏移（[start, end) 半开区间）
```

- `to_dict`：`spans is None` 不落键（**无格式文档逐字节不变**，重烤面
  收敛到「真的带行内格式」的样本）；`from_dict` 容错非法 span（越界/逆序
  丢弃该 span 并记 `rule_note`，宁漏勿误）。
- `SCHEMA_VERSION` 14→15；`blocks` 表：span 存 JSON 文本列 `spans_json`
  （NULL = 无），DDL 无条件幂等重放（决策 D1 机制），`DB_VERSION` 同批递增。

### 3.2 S1 证据 → S3 装配

- DOCX：`_docx_para_line` 装配 text 时记录每个 run 的 `[start, end)` 与
  格式 → `Line.spans`；表格单元格同口径。
- PDF：`Line.chars` 逐字符格式 → 行内 span 合并（相邻同格式字符聚合）；
  跨行 span 的拼接与 O-01 的 space 证据同机制穿线（`_join_line` 系列）。
- S3 跨行合并时 span 偏移平移；块级 uniform marks 保留（作为 span 的
  兜底渲染路径，二者不并存——有 spans 时忽略块级 marks）。

### 3.3 S4 渲染红线（新增 gate 的靶点）

- 不越界：span end ≤ len(text)，越界 span 整体丢弃（S1 容错兜底）；
- 不交叉嵌套：同层 span 重叠时按「先开始者赢、后开始者截断到前者 end」，
  嵌套（粗体含斜体）按 `**…*…*…**` 合法嵌套序渲染；
- 围栏/代码块内不渲染任何 span；
- 契约断言沿用 `assert_render_contract` 的模式：默认档渲染后做标记配对
  校验（`**`/`*`/`~~` 计数配对），破损即 AssertionError。

### 3.4 分阶段

| 阶段 | 范围 | 重烤面 | 退出判据 |
| --- | --- | --- | --- |
| 1 | DOCX run 级（证据最干净，无几何推断） | DOCX 语料 + 黄金样本 | 契约断言全绿；无 span 语料逐字节不变 |
| 2 | PDF char 级（需处理字距噪声合并） | PDF 语料 | 同上 + pdf_11 类定向样本 |

## 4. 风险登记

- span 偏移在 S3 各拼接入口（五入口 + heading merge）的平移是正确性主战场，
  必须 O-01 同款「逐入口穿线 + 反例钉住」的实施纪律；
- 编辑面（块文本改写）会使 span 偏移失效——`edits.py` 应用 op 时按 diff
  平移或整体丢弃该块 spans（保守：丢弃，回退块级口径）；
- FTS/检索不受影响（索引块 text）；API `blocks` 响应按需透出 spans。

## 5. 结论

不实施是**有意识的推迟**而非否决：块级 uniform 是可接受的保守站位，
span 模型的证据面与设计已登记，触发条件 T1/T2/T3 满足其一时按 §3 骨架
分阶段落地。在触发前，任何「顺手做一半」的中间态（比如只加字段不接渲染）
都是纯负债，明确不做。
