## 0. 先回答一个问题：已有 1341 条用例，为什么还要这套方案

现有测试体系很强，但它的强项与盲区同样明确：

| 现有资产 | 规模 | 强项 | 盲区 |
|---|---|---|---|
| `pytest -m gate` 红线层 | 572 项 | 契约、安全、退出码、等价性 | 断言的是「程序自己的行为」，不回答「好不好」 |
| `pytest tests/` 全量 | 1341 项 | 覆盖度高（语句覆盖 90%） | 覆盖率不等于正确性；`expected/` 基线是程序产物 |
| `tests/corpus/` 语料 | 22 份 | 端到端、可重烤 | **合成语料**，只证明「按约定输入时对」 |
| `tests/corpus/ideal/` | 22 份 | 标题真值、与管线独立 | **只有标题**（`kind: "headings"`），无表格/列表/代码真值 |
| `doc2md/qa_eval.py` | 3 指标 | char_f1 / heading_pr / table_col | 无 TEDS / NID / 规范 / 幂等 / 资产 |

**一句话缺口**：现有体系能证明「稳定」，不能证明「对」；能度量「标题」，不能度量「表格、顺序、规范」。

参考资料给出的判断标准正好命中这个缺口：

> 保真度用 NED + TEDS + NID + MHS 分层报（别只看综合分）；一致性用幂等率 +
> 往返 diff + lint 单规则命中率 + 资产完整率；没有标注就用**结构清单比对** +
> 数值勾稽 + 字段抽检。

本方案把这四组指标全部落地，并补上本轮实测暴露的能力缺口。

## 2. L1 代码缺陷检测

### 2.1 静态层

| 手段 | 命令 | 定位 |
|---|---|---|
| 既有 lint | `ruff check doc2md tests config ops`（口径 F+E+I） | 未用导入、未定义名、风格 |
| **静默失败扫描** | `tests/qa/scan_smell.py`（本方案新增，见 §6） | `except: pass`、裸 `except Exception` 无日志、`return None` 掩盖错误路径 |
| **契约漂移扫描** | 复用 `tests/test_ch477_version_sync.py` 的四条对账 | 版本号 / 编号 / 文档锚点三处漂移 |

重点提示：`doc2md/` 里「异常处理吞掉上下文」是本项目最值得扫的一类。规格要求「错误必须显式抛出、错误信息含调试上下文」，但 `except Exception: return None` 的形态会让门禁失败原因不可追溯。

### 2.2 动态层：以覆盖率缺口为导航

当前语句覆盖 90%（743 miss）。**不看绝对值，看集中在哪**：

| 模块 | 覆盖 | 性质 | 建议 |
|---|---|---|---|
| `doc2md/__main__.py` | 0% | CLI 入口 | 补 smoke：至少断言可导入 + `--help` 退 0 |
| `security/perms.py` | 40% | **权限是 NFR-20 的落点** | 优先补：700 权限、跨卷降级 |
| `pipeline/legacy_doc.py` | 69% | `.doc` 后端分派 | 补 `none` / 后端不可用 → E4151 |
| `ops/tmpclean.py` | 79% | 定时清理 | 补保留期边界 |
| `worker.py` 449–486（38 行） | 0 | **租约/所有权主逻辑**（B-27） | 优先补：租约过期回收、跨进程所有权 |
| `cli.py` 707–744（38 行） | 0 | CLI 分支 | 补退出码 2/4/5 分派 |

纪律：覆盖阈值**不设红线**。参考资料与本项目 §8.1 同口径——阈值红线会逼出「为覆盖而写测试」。覆盖数字进 CI 信息面，缺口清单进本方案维护。

### 2.3 边界与异常层

| 方法 | 落点 | 判据 |
|---|---|---|
| 边界值 | 空文档 / 单行表 / 0 页 / 单字符标题 / 超长查询串 | 既有 `qa_eval` 边界 gate 已钉，扩展到本方案指标 |
| 错误推测 | 截断 PDF、损坏 zip、加密 PDF、符号链接环 | `E4151/E4221/E5031` 逐码对账（见 §3） |
| **等价类（本项目最重要）** | 分片 ≡ 单片、串行 ≡ 批量、zip ≡ md 直出 | G6 字节等价，逐条目 sha256 全等 |
| **幂等（新增）** | 同输入连跑 3 次 | 输出 sha256 全等，`IDEM = 1.0` |

> **幂等率是开关不是分数**。参考资料：只要低于 1，说明管线里有非确定性来源（采样、并行乱序、随机文件名），此时其他分数全部不可信。本项目默认 `llm.mode=offline` + 无网络，`IDEM` 应为恒定 1.0（本轮实测 **1.0000** ✅）。

## 4. L3 转换效果评估（本方案的核心增量）

### 4.1 指标体系

```
保真度（需真值）                  一致性（不需真值）
├─ NED   文本保真  1−ED/max(len)   ├─ LINT  规范合规  加权违规密度
├─ BSF   结构保真  块对齐 F1        ├─ ASSET 资产完整  链接/锚点可解析
├─ MHS   标题层级  F1 × 层级准确率  ├─ IDEM  幂等      N 次输出哈希一致
├─ TEDS  表格保真  树编辑距离       └─ RENDER 渲染红线（项目扩展）
└─ NID   阅读顺序  1−indel/max
                                   项目扩展
                                   ├─ HONEST 降级诚实度（降级须留痕）
                                   └─ TCOLC  表格列一致率（S3 row_shape）
```

**两条必须守住的口径**：

1. **双口径纪律**：`expected/`（程序产物基线）只用于回归漂移；`ideal/` + 源端直抽才用于质量打分。两者**分列，不聚合**。
2. **LINT 分层**：规则分为**契约类**（命中即指向转换器缺陷：MD001/003/040/045/055/056/009/012/047）与**方言类**（只是风格偏好：MD025/060/022/031/026）。
   > 典型：MD025「一个文档只能有一个 H1」——源文档有 39 个章级标题时产物就该有 39 个 H1。拿方言类规则扣分，是在惩罚「忠实还原」。**门禁只卡契约类**。

### 4.2 三级真值体系（解决「没有标注怎么办」）

参考资料给了三层代理指标，本项目据此建三级真值：

| 级别 | 来源 | 可信度 | 覆盖 | 落地 |
|---|---|---|---|---|
| **T1 人工/程序标注** | `tests/corpus/ideal/` | 权威 | 标题（22 份） | 已存在，本方案直接消费 |
| **T2 源端直抽** | `srcstruct.extract()` | DOCX=真值级；PDF=启发级 | 标题/表格/列表/代码/链接 | **本方案新增** |
| **T3 结构清单比对** | 源端骨架 ↔ 产物骨架 | 骨架级 | BSF / NID / TEDS | **本方案新增** |

**T2 为什么成立**：DOCX 是 OOXML，`w:pStyle` 给标题层级（不是按字号猜——参考资料明确要求「尊重文档声明的结构」）、`w:tbl` 给表格、`w:numPr` + 字面符号给列表。它**不经过管线任何环节**，因此与产物彻底独立。

PDF 侧诚实标注能力边界：**无结构层，只能靠字号约定与线框检测**。无线框表拿不到，宁可返回空集也不猜（与 S3「宁漏勿误」同纪律）。

### 4.3 有序骨架：一个必须避开的坑

BSF / NID 比的是**顺序**，顺序只能来自源端：

- 错误做法：先列全部标题、再列全部表格（分类骨架）→ docx_11 的 5 张表夹在章节之间时，NID 只有 **0.27**，而真实顺序是逐节交错的。**这是参照系构造错误，不是管线缺陷。**
- 正确做法：`srcstruct.ordered_skeleton()` —— DOCX 走 body 元素序（真值级），PDF 走 `(page, top)` 几何序（启发级）。

修正后本轮 `order_nid` 由 0.9099 → **1.0000**。这个 0.09 的差，全部是我的度量方法错，不是产品错。

### 4.4 门禁阈值（按文档画像分档）

| 画像 | 适用 | 门禁 |
|---|---|---|
| `financial` | 合同 / 财报 | `table ≥ 0.90`、`text ≥ 0.98`、`lint_contract ≥ 0.95`、`idempotent = 1.0` |
| `academic` | 论文 / 研报 | `order ≥ 0.90`、`table ≥ 0.85`、`lint_contract ≥ 0.95` |
| `manual` | 手册 / 文档站 | `structure ≥ 0.95`、`heading ≥ 0.90`、`asset = 1.0` |
| `batch` | 批量入库（无标注） | `lint_contract ≥ 0.95`、`asset = 1.0`、`idempotent = 1.0` |
| `generic` | 默认 | `lint_contract ≥ 0.95`、`asset=1.0`、`idempotent=1.0`、`render=1.0` |

`idempotent` 与 `render` 恒为 1.0，不设「接近 1」的余地。

> CH-501 Task 8 补入 `S3 × D05`（点线引导符，B-44 发布阻断）：§12.7 标了「发布阻断」的难度必须有十字段卡，只写在 `test_hard_gate` 的 xfail 里等于交付面上不存在。该纪律由 `test_release_blocking_gaps_have_cards` 钉住（阻断集合与 B 号都从文档 / `KNOWN_GAPS` 派生）。`D04`（断词）与 `D12`（文本框）目前没有登记中的 B 号，暂不占卡位。

### 5.4 抽样纪律（最容易踩的坑）

> 表格分数对样本构成极度敏感——一个 64 页抽样若表格密度是全集的四倍，表格得分会朝引擎弱项移动**两位数**。

因此：**golden set 必须分层抽样并固定**，绝不能每次随手挑几十页。本方案的语料构成固化在 `manifest.json`（22 份）+ `hard/expectations.json`（10 份，D01–D10），构成变动必须显式登记。

```bash

# 按文档画像跑门禁（财报口径）
```

## 8. 本方案的能力边界（诚实标注）

1. **TEDS 行列不等价**：参考资料称「丢行惩罚重于丢列」（0.8125 / 0.84375），但**本实现实测相反**——丢列时表头与每个数据行各删一个单元格、代价随行数放大，丢行在序列层只记 1。已由 `test_teds_column_loss_penalty_exceeds_row_loss` 钉住，防止有人照抄参考资料数字把正确实现改错。金融表格优化时用 TCOLC 交叉验证。
2. **PDF 侧真值是启发级**：字号约定 + 线框检测。无线框表、旋转页、RTL 不出数——**不出数 ≠ 满分**，调用方不得把 `None` 当 1.0 聚合。
3. **语义等价无好指标**：`\frac{a}{b}` 与 `\dfrac{a}{b}`、全半角差异会被判为不同，反之真正的语义错误又扣得不足。表格语义评估目前只能靠 LLM-as-a-judge，尚缺与人类判断一致性的验证——本项目不引入。
4. **合成语料 ≠ 真实文档**：`hard/` 仍是 reportlab 生成，只是把难度档补齐了。结论外推到真实业务文档前，必须过 P4 的真机样本。
