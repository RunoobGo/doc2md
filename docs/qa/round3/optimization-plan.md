## 2. P0 改进项

### OPT-15 S1 行装配几何化：跨页表整列脱落（HD-1 / G8，B-43）

**问题回顾**
`hard_02_cross_page_table.pdf` 声明 1 张 3 列 × ≥41 行，实测裂成 `table[0]` 2 列 × 37 行（表头只剩 `序号/科目`）+ `table[1]` 3 列 × 5 行，`金额` 列整体脱落成正文串 `金额10011002…1036`，`ir.warnings` **0 条**（`/tmp/qa-r4/run_hard_final.log`）。

**改进内容（策略）**
1. **判据从文本流顺序改为几何归属**：`RawPage` 已带字符级坐标，行装配先按 y 容差聚类成行，再按 x 与表头列位配对；列归属的判定输入是坐标，不是 token 相邻顺序。
2. **续表识别**：跨页时若第 2 页首行的列数与上一页表体一致（或与表头列数一致），并入同一 table 对象；表头重复行去重。
3. **入账必须显形**：任何「本应有 N 列、实际只配到 M 列」的落差都挂新告警（与 `W1045` 同族，建议 `W1048` 列归属降级），杜绝 3.3 更正过的那类无声缺口。
4. **回归护栏先行**：D01（无边框表要求「无边框也成表」）与 D06（数值形态）必须与 D02 同批跑，否则几何化判据很容易把 D01 推红。

**落地模块**：`doc2md/pipeline/s1_parse.py`（PDF 行/列装配）；告警码 `doc2md/errors.py`；结构断言 `tests/corpus/run_hard.py` → `tests/qa/test_hard_corpus.py`（见 OPT-17）。

**预期收益**：数字/财务类文档的表格保真——这是本管线最高价值的正确性面；同时补齐降维账本的入口缺口。

**回归验证**：难度样本 D02 结构断言转绿 + D01/D06 不回退；22 篇语料逐字节 + 320 页金样本人工复核；`PIPELINE_VERSION` 契约级升位；门禁层（OPT-17 入门禁后）跑通。

**风险与取舍**：改动必然动产物字节（G5 排队口）；且「哪一列对应哪个表头」的最终判定**只能由人工逐页对照源 PDF 给出**——本机可以把判据写对形状，无法自证列归属正确 → **受限，只登记不实施**（B-43）。

### OPT-16 目录识别与 run 间空格保真（HD-2 / G8，B-44）

**问题回顾**
`hard_05_leader_dots.pdf` 声明含 `第一章 总则` / `第二章 职责` / `第三章 附则`，实测三者全缺，产物为 `| 第一章总则 | .................... | 1 |`，`ir.warnings` **0 条**。三个子缺陷：引导符成独立单元格、整页目录误判为表格、run 间空格丢失使词塌连。

**改进内容（策略）**
1. **先修字符级保真**（独立、最小、可本机自证）：run 拼接时空格不得丢。这一条与目录识别无关，单独就足以破坏检索面（用户搜 `第一章 总则` 搜不到），应拆成独立提交。
2. 再立目录页判据：引导符密度 + 行末页码右对齐 + 行数形态三类特征联合，且**必须与 OPT-15 的表格判据同调**——无边框目录要判成段落表，无边框数据表要判成表格，两侧用同一套特征而不是两条互不知情的规则。
3. 引导符不入单元格：识别为目录后按 `章节名 <引导符> 页码` 输出为普通行（或目录块），点线序列降为排版噪声。

**落地模块**：`doc2md/pipeline/s1_parse.py`（run 拼接、行分类）、`doc2md/pipeline/s3_structure.py`（表格/目录判别）。

**预期收益**：目录页可读；检索面恢复；`hard_04` 的断词缝合与 `hard_05` 的空格保真共用同一处修复。

**回归验证**：D05 三个期望串命中；D01/D02/D06 表格面不回退；D04 断词不回退；语料逐字节复核。

**风险与取舍**：三阈值的**误判面无法由本机合成样本界定**（正文里的点线填空会不会被误判成目录，需要真实目录页语料 + 人工抽检）→ **受限，只登记不实施**（B-44）。字符级空格保真那一条不受此限，可在 CH-501 单独实施并重烤。

### OPT-17 难度腿结构断言入门禁 + D03 补位（G9 / O-g，B-46；前置 OPT-15/16）

**问题回顾**
D02 的裂表在 `tests/qa/test_hard_corpus.py` 里是一条 `pytest.skip("TODO 未填断言")`——骨架只核对 `contains`/`not_contains`，不看 `tables`/`headings`。于是「1390 项全量 + 580 门禁 + 22/22 语料全绿」与「两份样本存在高影响结构损伤」同时成立。另外 `gen_cases.py` 从未生成 D03，编号序列留了一处空洞。

**改进内容（策略，本机可自证，且**应最先做**）**
1. `run_hard.py` 的结构对账（`tables` 的 ncol/nrow/header + `headings` 的 level + `behavior`）落进 pytest 红线，用 `--pytest` 生成或手写均可，但断言面必须覆盖 `expectations.json` 的**全部声明字段**；未声明字段不得凭空补。
2. 骨架里禁止出现「TODO 未填断言 → `pytest.skip`」：声明了却没断言的字段一律显式 `fail`，缺失样本文件同样 `fail` 而非 skip（本轮 D07 生成器自删缺陷正是被 skip 掩盖的）。
3. 入门禁的时机绑定 OPT-15/16 闭合（否则门禁长期红）；在此之前先把 `run_hard.py` 作为**独立的收口必跑项**写入 README/dev-plan 取证清单，红也要显形。
4. D03 需要人工决定补哪个难度形态——当前序列缺的不是一个样本，是**一个尚未被想到的失效形态**；本册不临时凑数，登记为人工待办。

**落地模块**：`tests/qa/gen_cases.py`（骨架模板）、`tests/qa/test_hard_corpus.py`、`tests/corpus/run_hard.py`、`tests/corpus/hard/`。

**预期收益**：把「唯一独立于产物的真值腿」从信息层升为门禁层，使 OPT-15/16 的改动可判定、且改完不会再次静默回归。

**回归验证**：门禁项数增加需在 `test_ch498_gate_budget.py` 的慢项清单冻结口径里同步；`pytest -m gate` 与三档 merge-gate 计数需在远端腿复证（B-12/B-16）。

**风险与取舍**：入门禁后 D02/D05 未修前门禁会红——因此本项的正确顺序是「先做 1/2/3 的断言落盘但标记为 `corpus`，OPT-15/16 闭合的同一批切 `gate`」，而不是反过来放宽断言。


### OPT-1 采集面从「部件枚举表」升级为「可见内容契约」（N1 / G1，B-33）

**问题回顾**

- `doc2md/pipeline/s1_parse.py:19` 的模块文档逐部件声明 DOCX 采集范围（正文 / 脚注 / 尾注 / 编号 / 样式），页眉页脚部件不在表内；全仓 `doc2md/` 下 `sectPr`、`w:header`、`w:ftr`、`headerReference` **0 命中**。
- TC-M2-08 实测 `header_hits=0 footer_hits=0 warnings=[] blocks=2`：内容静默丢弃，`ir.json` 与 `report.html` 均无任何提示。
- 根因形状：降维有账本（W1043/W1044/W1045/W1046），未采集没有——告警码的语义前提是「S1 知道有这个东西」。

**调整策略（分两步，第一步本机可自证）**

1. **第一步（可实施）：把「未采集」变成可见事实。**
   - S1 在 DOCX 解析时枚举包内部件（`word/header*.xml` / `word/footer*.xml` 是否存在、各含多少段落），写入 `ir.meta.uncollected`；
   - 立 `W1047`（新增告警码，语义 = 源中存在但按当前 ADR 不采集的内容），逐类报数而不报正文（NFR-20 无正文泄露红线不破）；
   - `report.html` 与 `doc2md doctor` 输出「本页面无正文丢失风险，但有 N 项内容未采集」。
   - 这一步**不改正文产物字节**（只加 `ir.meta` 与告警），可先于 ADR 决策落地，把「高」等级项从「静默」降级为「可见」。
2. **第二步（需决策）：页眉页脚是否进产物。**
   - 三个候选：(a) 逐页附注（`> 页眉：…` 引用块）；(b) 文档头聚合一次；(c) 保持不采集但永久带 W1047。
   - (a) 保真最高但产物膨胀、重复页眉会产生 N 份噪声；(b) 丢失「每页不同页眉」语义；(c) 最小风险但用户仍需读文档才知道边界。
   - **本册推荐 (b) + 页眉变化时升级为逐节出现**：与现有「块级」IR 粒度一致，不需要 span/section 级新模型；但这是产品决策 + 需人工审阅 11 篇 DOCX 产物，按纪律只登记（B-33）。

**预期效果**：任何一篇 DOCX 的产物都能自证「我采了什么、没采什么」；W1047 使审阅者在打开 MD 之前就知道有内容不在 MD 里。

**涉及模块**：`pipeline/s1_parse.py`、`ir/model.py`、`errors.py`（新码）、`pipeline/s4_render.py` 或 `report` 生成侧、`docs/dev-plan.md` 附录、`tests/`。

**回归验证**：第一步需新增夹具（含页眉 / 含页脚 / 首页不同 / 奇偶不同 / 空页眉），断言 `uncollected` 计数与 W1047 触发、正文产物字节不变；第二步需语料 22 篇重烤 + 11 篇 DOCX 人工审阅。

**风险与取舍**：W1047 会让「所有带页眉的 Word 文档」都出一条告警，报告页需要聚合展示，否则告警噪声会淹没真正重要的 W1044/W1045；这是可见性修复的必要代价。

### OPT-2 探针反空跑红线（O-a / O-b / O-c / G6）

**问题回顾**

- 本轮 111 项探针首跑有 4 项给出假信号（3.6%）：`if len(ids) >= 2` 使翻页用例在命中不足时静默跳过；`--full` 检索只断言 `rc == 0`，0 命中也算过；`has_bare_script` 用子串判断「裸标签」被 `\<script>` 误判；端点数用 22/19/21 三种分母混比。
- 共同形态：**判定式里含有一个让断言在「什么都没测」时也成立的前件**。产品侧的同构缺陷就是 N3（G3）。

**调整策略**

1. 在 `tests/conftest.py` 增加共享断言助手（与既有 `_need`/`_missing` 同处），把「样本非空」变成显式前置：
   - `require_hits(rows, minimum, subject)` —— 少于 `minimum` 即 FAIL 并打印取样口径；
   - `assert_no_vacuous(collection, check)` —— 校验循环体至少执行过一次的通用形态；
2. 探针/测试编写规范写入 `docs/review-round*.md` 的纪律小节与 QA 模板：**任何「足够才继续」的分支必须配「不足即失败」的 else**；
3. 结构存在性判断禁用裸子串：HTML/标签类判定统一走「未被反斜杠转义的 `<`」正则（本轮 V-PIPE-17b 的形态），并在测试侧提供一条常量正则复用，避免每条探针再写一遍；
4. 跨面一致性校验统一为「先声明分母口径 → 再做集合双向差」（本轮 V-API-18 的形态），禁止数值比对；
5. 任何参与阶段清单的计时项必须断言 `>= 0` 且基准一致，否则从占比表剔除并显式命名伪阶段（O-d）。

**预期效果**：下一轮的 PASS 全部可追溯到「确实取到了 N 条样本」；假信号率从 3.6% 压到 0（结构性消除，而非靠人仔细）。

**涉及模块**：`tests/conftest.py`、`/tmp` 探针脚本（沉淀为 `tests/qa/probes/`）、QA 文档模板。

**回归验证**：助手本身用「命中不足」「空循环」两类负夹具钉住（必须 FAIL）；把本轮 4 项已修正探针改走助手后重跑，结果应仍 49/49 · 32/32 · 30/30。

**风险与取舍**：沉淀探针脚本会新增测试收集数（当前 gate 580 / 全量 1390），需与门禁耗时预算一起看；但**把证据留在 `/tmp` 是可重现性缺陷**，收益大于成本。另需防「助手被当作万能豁免」——助手只保证样本非空，不保证断言本身有意义（本轮 O-g 正是「样本在、断言面只覆盖声明的一半」）。

### OPT-3 S1.5 孤儿键收口（N2 / G2，B-32）

**问题回顾**

- `doc2md/pipeline/s1_5_gate.py:231-246`：`reject_on_any` 只在 `mode != "auto"` 分支被消费，而默认档就是 `auto`。TC-M3-02 实测 `auto_on=(True,[])` 与 `auto_off=(True,[])` 完全相同，`even5` 档才生效（`page 1: chars=37 < 120`）。
- CH-424 把 auto 改成 run/ratio/all_pages 三条判据后，该键成了没人读的孤儿键，但 `docs/dev-plan.md` 曾把它描述成 auto 的总开关。文档口径本轮已按实况改正，键的存废未决。

**调整策略（三选一，需外部样本定档）**

| 方案 | 内容 | 代价 |
| --- | --- | --- |
| A | `auto` 也读该键（true 时单页坏即拒收） | 默认档拒收面扩大，线上误杀风险未知——**必须先有真实语料误拒率** |
| B | 从配置面删除该键，`even5/legacy3` 固定「任一坏页即拒收」 | 破坏既有配置文件兼容（需 loader 容忍未知键或给迁移提示） |
| C（推荐起点） | 保留键但把它改名/挪档为 `s1_5.even_reject_on_any`，`auto` 明确声明不消费 | 仍是契约变更，但语义诚实，误杀风险为零 |

**受限原因**：本机 22 篇语料样本不足以评估「任一坏页即拒收」的误杀面；需外部语料 + 人工抽检拒收清单。**建议执行顺序**：外部语料跑 A/C 两档 → 人工比对拒收差异 → 定档 → 实施 + loader 兼容测试。

**验证方式**：三档（`auto` / `even5` / `legacy3`）× 键的每个合法取值构成参数化矩阵，断言「配置面上存在的键必在某一档被消费」；再加一条静态红线：`config/default_toml.py` 声明的每个键都能在 `doc2md/` 中找到消费点（G2 的结构性防复发）。

**风险与取舍**：选 A 会把「采样页刚好字少」的正常文档拒收；选 B 会让用户已有的显式配置启动报错。三案都比现状（静默无效）好，但不能由本机自证。

### OPT-4 LLM 探活契约去条件化（N3 / G3，B-42）

**问题回顾**

- `doc2md/llm.py:606` `_candidate_indices()` 判无候选 → `payload_batches()`（`llm.py:784-790`）返回 `[]` → `repair()` 的 `for payload in payloads`（`llm.py:696`）一次不执行 → 不发 HTTP、不抛 `LlmServiceError` → `pipeline/convert.py:333-344` 的 except 分支不可达。
- TC-M7-04 实测 `rc=0 status=ok`、报告 `source=server batches=0`；只有自建含候选块文档才复现 E5041/rc=4（TC-M7-03）。契约「服务不可用必须当场可见」被实现成「请求失败时可见」。

**调整策略**

1. `LlmClient.repair()` 在 `payloads == []` 时执行一次 `self.probe()`（GET `/health`），把结果计入 `llm_stats`（新增 `probe_ok` / `probe_stage` 两个计数字段，不含正文，NFR-20 不变）；`probe` 失败且 `fallback=false` → 同一套 `LlmServiceError(stage="health")` → E5041；
2. `source` 拆成 `server` / `server-untouched` 两值（无候选且未探活的旧口径不再存在，因为第 1 步保证一定探一次）；
3. 文档与 `doctor` 输出同步：`llm.mode=server` 的健康判定不再依赖文档内容；
4. 泛化检查项（写入 QA 纪律）：**以「失败可见性」为内容的契约，必须枚举触发路径的输入域**，并为未触达路径显式命名。

**受限原因**：`llm_stats` 进 `report.html`，改动即产物字节变化，需黄金重烤；且「无候选算不算服务失败」属契约决策。**验证方式**：起 / 不起 llama-server 两种环境跑同一文档，比对退出码与 report.html 的 LLM 表；语料 22 篇 + 自建候选文档各一遍。**建议执行顺序**：与 OPT-1 第一步、OPT-8 合并为同一次重烤批次（见 OPT-5）。

**风险与取舍**：给零候选文档增加一次 `/health` 请求（≈毫秒级，离线断言 `run.offline_assert` 允许 loopback）；对纯离线部署（`mode=offline`）零影响。反对意见是「无候选时服务健康与否与本篇无关」，但运维侧的判据一旦依赖输入分布就不可靠——这正是本轮要消除的形态。

### OPT-5 产物字节冻结解耦（G5，工程性阻塞项）

**问题回顾**

- B-33（页眉页脚告警）、B-37（转义单源）、B-38（页区间并行）、B-42（探活）四项互不相干，却被同一道「必须重烤 22 篇语料黄金 + 人工复核」挂住。字节冻结是正确的回归防线，但当它成为单点排队口时，任何改进都得等批次。

**调整策略**

1. **分层验收**：把产物回归拆成三层——
   - 结构层：成员集合（`content.md` / `ir.json` / `report.html`）、`pipeline_version` 戳、schema 键集、双产物等价（`bytes=661 zip_md=661` 已有此类断言）；
   - 语义层：块类型序列、告警码集合、表格列数、标题层级；
   - 字节层：仅对**未申报变化**的内容做逐字节 diff；
2. **diff 白名单**：新增告警行、转义列等「本轮申报的预期变化」列入 allowlist，其余字节必须一致——把「人工复核 22 篇」变成「机器复核 + 只看白名单外差异」；
3. 重烤脚本化（`tests/corpus/` 侧）：一条命令产出「哪几篇、哪一类差异、差异行数」，作为 PR 证据附件。

**预期效果**：单项产物面改动的人工复核成本从「读 22 篇」降到「读差异清单」；OPT-1/4/8 可并行推进而非串行排队。

**涉及模块**：`tests/corpus/run_corpus.py`、`tests/`（黄金比对）、`docs/dev-plan.md` 12.x 发布检查清单。

**回归验证**：用一个「故意新增一行告警」的临时补丁跑三层，确认结构/语义层通过、字节层只报该差异；再用一个「意外改变正文字符」的补丁确认字节层拦住。

**风险与取舍**：白名单机制可能被滥用为「差异都塞进 allowlist」。约束：白名单只允许**键名/行数级别**的模式（如「新增 W1047 行」），不允许逐篇正文豁免。本机可自证。

### OPT-6 页区间并行（性能唯一大杠杆，B-38）

**问题回顾**

- 两轮独立实测：审阅轮 1 段 12.68 s / 2 段 7.89 s（1.61×）/ 3 段 4.55 s（2.79×）；本轮 1 段 10.04 s / 2 段 5.65 s（**1.78×**）/ 3 段 3.80 s（**2.64×**），且 `lines=15613` / `pages=320` 逐字节一致、各档内层耗时相加 ≈ 单段墙钟——加速来自并行展开，不是少算了活。
- S1 占单篇 97.4%，这是唯一能改变墙钟的量级。

**调整策略（先证等价，再谈实施）**

1. **第一步（本机可自证）：跨段依赖逐字节等价性证明。** 三处已知依赖必须逐一钉死：
   - 跨页折行并回（片尾行与邻片首行的接续）；
   - `modal_size` 是全文档众数（分段各自取众数会漂移）；
   - S1.5 门禁的全量判定（`all_pages_empty`、空页占比、连续坏页成段都需全局页序）。
   产出物：一个等价性脚本，对 320 页金样本按 1/2/3/4 段切分后重拼，断言与整篇解析**逐字节相同**（含 `ir.json` 与告警集合）。
2. 第二步（契约级改动）：`PIPELINE_VERSION` 升位 + 分段调度实现（进程池，段边界按页区间），worker 侧注意 RSS（320 页单段 236.8 MB，N 段并行内存近似相加，需按 `min(核数, 页数)` 与内存预算取上限）；
3. 第三步：语料 22 篇 + 全量套件 + 门禁耗时复核（gate 当前 40.6 s，不得因新增并行路径的测试而劣化）。

**预期效果**：320 页档墙钟从 ≈10.0 s 降至 ≈3.8 s（2.6×）；单篇小文档不变（不足分段阈值时走单段）。

**受限原因**：实施属契约级改动且必须先有第一步的等价性证明；第一步本机可做，第二步改动产物字节需与 OPT-5 的批次合并。**建议执行顺序**：OPT-5 → OPT-6 第一步 → 裁定 → 第二步。

**风险与取舍**：并行会把「解析顺序」从隐式保证变成需要显式合并的逻辑，块 ID 稳定性与告警去重是新失败面；宁可只做「≥N 页才并行」（如 ≥150 页）也不在短文档上引入不确定性。内存与 CPU 抢占对 resident worker 的既有吞吐有影响，需与 worker 并发度一起定档。

### OPT-7 绕过 pdfplumber per-object 展开（B-39）

- 事实：320 页 / 60 万字量级下峰值 RSS 236.8 MB，近线性（40 页 83.0 MB / 1 页 59.7 MB）；`_page_chars` 逐对象构造 `LTChar` 是主要分配源。
- 方向：直接用 pdfminer 的 `CTFont` 度量层取文本，跳过 pdfplumber 的对象包装。
- **受限原因**：等价面极宽（旋转页、连字、CJK 宽度、`/ToUnicode` 映射），需逐文档比对才能证明无回归；本机 22 篇语料覆盖不了旋转/连字的真实分布。
- **验证方式**：320 页金样本 + 语料 22 篇逐字节比对 + RSS/墙钟双指标（目标：320p RSS ≤150 MB，墙钟不劣化）。
- **建议执行顺序**：OPT-6 之后（并行已拿到 2.6× 时，单点内存优化的紧迫性下降）；或与 B-35 真值集建设同批做逐文档比对。
- **风险与取舍**：改的是解析根基，回归面最大、可验证性最弱，属「收益次于 B-38 但风险最高」的一档——不建议在无逐篇比对能力时实施。

## 4. P2 改进项

### OPT-8 转义单一来源（G4 / B-37）

- 事实：源文本 → Markdown 字面量的规则写了三遍——`s1_parse.py:1108-1113`（DOCX 单元格预转义 `&`/`<`/`>`）、`s3_structure.py:550-559`（`cell_md` 硬编码逐对 replace，转义 `<` 但**不转义 `&`**）、`s4_render.py:77-105`（`_INLINE_ESCAPE_TABLE` + 四条行首正则）。实测：同一篇文档正文里的 `&` 走 `_escape_text`、表格里的 `&` 不走；字面 `a&amp;b` 在 DOCX 单元格输出为 `a&amp;amp;b`。
- 策略：抽出 `doc2md/pipeline/escaping.py` 作为唯一出口（行内集 + 行首集 + HTML 实体策略三组语义），S1/S3/S4 全部改为调用它；单元格不再预转义、由 S3/S4 统一按上下文转义。
- 预期效果：同一字符在所有出口口径一致；新增出口不会复制第四套规则。
- 回归：语料 22 篇 + 含 `&`/`<`/`\|`/字面 `<br>` 的表格夹具；对既有输出做 diff，确认差异仅限转义口径；黄金重烤与 OPT-1 第一步 / OPT-4 合并同批。
- 风险与取舍：改任一侧都动产物字节，需人工比对若干含 `&` 的真实表格文档（外部样本面）；不提供「关闭转义」开关，只允许显式 opt-in 的调用方承担风险。

### OPT-9 产物结构回读校验（4.2 残余）

- 事实：`_contract_violation`（`s4_render.py:215-227`）只扫 `_ANCHOR_MARK` 与 `~~`；本轮已接进生产路径逐块调用并豁免代码块（实测 `E5031 detail={'reason':'render_contract','marker':'<script','block_type':'table'}`，代码块 `len=34` 不误杀）。但标记字符串扫描永远抓不到「单元格 `&` 双源」这类结构分叉。
- 策略：新增**测试/演练专用**的结构回读校验——用 Markdown 解析器把 `content.md` 读回，断言块类型序列、表格每行列数、标题层级与 `ir.json` 对齐；生产路径保持零依赖。
- 预期效果：D2/D3/D4 类问题从「靠语料碰巧覆盖」变成「任何夹具都能判定」；OPT-2 的断言助手与它天然配套。
- 回归：对现有 22 篇语料跑回读，差异清单为空即基线成立。
- 风险与取舍：引入 dev 依赖（如 `markdown-it-py`），需确认只进 test extra、生产 `dependencies` 不变；这是可本机自证项，建议 CH-501 优先做。

### OPT-10 `security/perms.py` 覆盖补齐（G7）

- 事实：全量语句覆盖 `7797/740 → 精确 90.51%（coverage 打出 91%）`，但 `perms.py` 仅 `75 语句 / 45 未覆盖 = 40%`；本轮 RBAC 只端到端覆盖 reader 越权提交一条（`403 detail={'required':'editor','role':'reader'}`）。
- 策略：按「角色 × 动作 × 目录状态」矩阵参数化补测，优先覆盖失败分支（冻结键、不可消毒路径、符号链接逃逸、权限位不满足时的 `sanitize_fail_action`）；目标 ≥80%。
- 回归：覆盖率报告逐模块比对；判定逻辑改动一律不允许——只加测试，若加测试暴露缺陷则转入当轮修复。
- 风险：低；纯测试面。属可本机自证项。

### OPT-11 指标报告出口与真实 PDF 标注（G6 / B-34 解除依赖 + B-35 重新定界）

**事实（本轮收口更正，见对照表 O-e）**

- 早前《审查》AR-11/AR-12 写「PDF 标题无独立真值、F1=1.0 属自证循环」——**回文件核对后不成立**：`tests/corpus/ideal/` 已有 21 份标注（DOCX 11 份 / 111 标题、PDF 10 份 / 102 标题），由 `make_ideal_docx.py`（python-docx 直读源 XML `Heading N`/`Title`）与 `make_ideal_pdf.py`（pdfplumber 逐行字号 + `make_corpus.py` 生成器的字号约定）从**源文件**导出，不经管线任何环节；`tests/test_qa_n03_ideal.py` 以 46 项断言钉住「标注 == 源重生成」「S3 F1 == 1.0」（`pdf_10` 要求 pred 空集，`pdf_06` 无文本层故无标注）。
- 真正剩下的两处：① 产品侧 `Result.metrics.heading_pr` 的 ref 取 S1 自己的 `Line.level_hint`（`pipeline/convert.py:388-398`），它证明的是**样式直通**；PDF 侧该键按设计不产出（`convert.py:551` 明示「缺真值显示 —，不是满分」）。② `tests/corpus/run_corpus.py` 只与 `expected/*.md`（管线重烤基线）做字节比对，**从不上报指标**——质量数字只以 pass/fail 断言存在（且在 1390 全量腿、不在 580 门禁腿），没有趋势视图。

**OPT-11a 指标 runner（本机可自证，无产物字节影响）**

- 策略：在 `tests/corpus/` 增加一个汇总入口，对 22 篇语料逐篇输出「对 `ideal/` 的 `char_f1` / `heading_pr` / `table_col`」表格，并把该表写入语料报告；断言阈值先只报不阻断，观察一轮误判分布后再决定是否进门禁。
- 预期效果：质量指标从「只有断言」升级为「有数字、有趋势、可比较」，为 OPT-11b 与标题分层改造提供基线；`heading_pr` 的 ref 一律改走 `ideal/`（不再用 `level_hint`），把「直通证明」与「准确率」两件事分开命名。
- 风险与取舍：runner 会增加全量套件耗时（22 篇逐篇算 F1），需评估是否只进全量腿不进 580 门禁；指标不得混用基线口径（`expected/` 只作漂移监控，`ideal/` 才是质量真值——`ideal/README.md` 的双口径纪律必须在 runner 里以字段名强制区分）。

**OPT-11b 真实世界 PDF 标注（受限登记）**

- 策略：对本机语料之外的真实 PDF（建议 10–20 篇、含扫描件/多栏/无显式字号层次的野外文档）做人工逐页标题标注，产出同格式 `*.ideal.json`，再据此评估启发式准确率与「元数据优先、启发式兜底」的分层改造收益。
- 受限原因：**必须人工标注**，合成语料的字号约定真值不能替代野外文档；本机无法自证。
- 验证方式：新标注集上 `heading_pr` 的 P/R/F1 分布 + 误判样例人工复核。
- 建议执行顺序：OPT-11a → OPT-11b（先有出口，标注到手即可直接读数）。
- 风险与取舍：标注一致性需双人交叉 + 仲裁，成本高于调一个阈值；但在野外真值出现之前，任何针对真实 PDF 的标题改动仍无法证明收益。

## 7. 总体风险与取舍

1. **「功能完整」与「产物字节稳定」不可兼得**：OPT-1/4/8/15/16 都改变产物面（告警、LLM 统计、转义口径、表格与目录结构）。取舍是合并批次 + 三层验收（OPT-5），而不是放弃功能完整性。**本轮的教训偏向另一侧**：因为怕重烤而不动 S1 判据，代价是 D02 的整列脱落一路带到收口才被独立真值腿抓到——重烤成本可以合并摊薄，正确性问题不能。
2. **性能优先不等于全面优化**：实测已证明 S2–S4 是噪声级，任何「优化渲染循环」的改动都是负收益（增复杂度、零墙钟变化）。性能预算全部押在 OPT-6（并行）与 OPT-7（内存）。
3. **并行引入新失败面**：块 ID 稳定性、告警去重、跨段门禁判定、worker 内存抢占。约束：等价性证明未过不实施；分段阈值保守（长文档才并行）。
4. **契约裁定的不可自证性**：OPT-3 与 OPT-4 的「算不算失败」是产品决策，本机无法证真；OPT-15/16 的「列归属对不对、目录阈值误不误判」同样只能由人工对照源文档判定。按纪律只登记，不猜。
5. **度量投入的机会成本**：OPT-2/9/11a/17 都不直接增加用户可见功能。判断依据是本轮 3.6% 的探针假信号率、一处已入文档的前提错误（O-e），以及**OPT-17 一类的断言面缺口——它单独就造成本轮 2 项高影响缺陷被四条全绿的自动化腿同时漏掉**。证据不成立或前提未复核时，后续所有轮次的判断都在打折。
6. **真值来源的取舍是硬约束**：任何新增的收口腿必须在设计期说明「期望值从哪来」。取自产物（重烤基线、管线自身指标 ref）的腿只能防漂移，不能防结构损失；本管线此前**没有任何一条门禁腿**满足「真值独立于实现」，OPT-17 是第一例。
7. **不做的事**：不为 P1 达标而放宽用例口径；不把 HD-1/HD-2 从「失败」改回「缺口」来凑达标；不对 `perms.py` 低覆盖用 `t.Skip` 或注释豁免处理；不把 `_tail` 伪阶段当作可忽略的显示问题而继续留在占比清单里；不在 B-40/B-41 的外部环境缺位时宣称相关平台面已验证；**不在骨架里用 `pytest.skip("TODO 未填断言")` 充当通过**。

## 8. 结论

- **收口改判后的事实**：核心面 92/95 通过、0 契约缺陷；新增的独立真值腿 4/7 通过、**2 项契约缺陷（HD-1 跨页表整列脱落、HD-2 目录误判 + 塌词，均零告警）**、1 项真值侧待裁定（N4）。合并 96/102 = 94.12%，P0 = 37/38。首稿「本轮 0 契约缺陷、遗留全是决策缺口」的结论不成立，本册已按 HD 证据改写。
- **最高性价比的可立即动作**：OPT-17（结构断言入门禁，是 OPT-15/16 的验收工具）+ OPT-2 / OPT-9 / OPT-10 / OPT-11a / OPT-14 / OPT-5 七项，全部零用户可见产物变化；最高业务价值的是 OPT-1 第一步（把「看不见」变成「看得见」）；唯一性能大杠杆是 OPT-6（2.6×，须先过逐字节等价关）。
- **本册的两处前提更正**：① OPT-11 拆分——B-34 的判据其实早已存在，只是没有报告出口，因此它从「依赖外部人工标注」改回「本机可自证」，受限清单因此**减少一项**；② OPT-15/16 新增——同一批对账里，本册的阻断项从 0 变 **2**，受限清单**净增三项**（B-43 / B-44 / B-45，另 B-46 以两者为前置）。两个方向都有，如实记的方向比只记好消息的方向更重要。
- 发布判定与建议：**工程侧本轮阻断发布**。TC-HD-02 是 P0 失败，按《测试文档》2.2「P0 失败即阻断」，闭合路径只有两条——OPT-15/OPT-16（B-43/B-44）在发布前修复，或人工逐页对照真实 PDF 复核后出具书面豁免。两者都需要人工介入，本轮按纪律只登记不实施。其余 B-32 / B-33 / B-42 / B-45 仍是需人工裁定或外部样本的待办，但不属阻断项。
- **下一条自 CH-501 起**：先落 OPT-17 与六个零字节项，再排 B-43/B-44 的人工对照窗口；`PIPELINE_VERSION` 只在 OPT-15/16 那一批做契约级升位，OPT-17 与其余六个只动测试面，不升版本。
