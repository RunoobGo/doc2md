- 文档编号：QA-D2M-2026-10-24-R3-ANA
- 输入：`docs/qa/round3/test-plan.md`（102 例 = 核心 95 + 难度腿 7；核心 92 通过 / 3 缺口，难度腿 4 通过 / 1 缺口 / 2 失败）、`docs/qa/round3/comparison.md`
- 被测版本：2.18.0 / SCHEMA 14 / DB 10 / PLAN 3.34
- 分析日期：2026-10-24（收口改判 10-25，见 1.1）
- 上一轮对照：`docs/qa/round2/deviation-analysis.md`（13 项偏差 D1–D13，根因 R1–R7）

## 1. 结论先行

### 1.1 收口改判

首稿的结论是「本轮没有新增契约缺陷」。该结论在收口时被自己新增的独立真值腿推翻：**D02（跨页表整列脱落 + 裂表）与 D05（目录引导符进单元格 + run 间空格丢失使词塌连）是两项契约缺陷，且都零告警**。首稿之所以为 0，是因为核心 95 例、门禁 580 项、全量 1390 项、语料 harness 22/22 四条腿的真值全部取自管线自身已认可的形态，结构损失在这四条腿上是不可见的。本册按改判后的事实写。

第二轮 13 项偏差复验全部闭合（见对照表第 4 节），错误码 14/14、告警 4/4 首次做到端到端构造。遗留问题因此是**五种形态**，沿同一套归纳可穷举：

1. **解析层**：采集面以「已实现的部件」为边界，而不是以「用户可见内容」为边界——页眉页脚从未进 S1，因此既不报错也不进降维账本（N1）。脚注/尾注在模块文档清单里，页眉页脚不在，这就是缺口的自证。**同一层的第二种形态由本轮新增**：行装配依赖 pdfminer 文本流顺序，跨页与引导符页因此整列脱落、误判成表，**且损失不进入任何告警**（HD-1 / HD-2）。
2. **映射/门禁层**：判定开关长在**非交付分支**上——`reject_on_any_bad_page` 只在 `mode != "auto"` 被读，而默认档就是 `auto`，于是配置面上「看起来有防护，实际没人执行」（N2）。
3. **生成层**：转义已经存在，但**没有单一来源**——同一字符在 S1 预转义、S3 单元格、S4 行内三处各有一套规则，`&` 的口径因此不对称（B-37）；红线只查少量标记字符串，无法在结构层发现这类分叉。
4. **校验/度量层**：一类是**契约可达性与输入域耦合**——零候选文档使 `llm.repair()` 的批循环一次都不执行，`fallback=false` 也回 rc=0，E5041 只在特定输入分布下可达（N3）。另一类是**证据自己不成立**：空跑断言、不严谨子串、混比口径、伪阶段计时、结论前提未回文件复核，加上本轮新增的**分档判据用反**、**骨架断言面窄于声明面**与**报告打出的整数被当作事实继承**（O-a…O-h）。前四项都不是产品缺陷，但每一项都足以让下一轮误判；后四项里 O-f 实际改变了本册的发布判定，O-h 实际改变了四处文档的覆盖率数字。
5. **真值来源层（本轮新立，独立于前四层）**：一条自动化腿能否发现结构损失，取决于它的期望**是否独立于被测实现**。`expected/*.md` 是管线重烤基线、`ideal/*` 来自合成语料的生成器字号约定，二者都不会对「掉了一列」报警；只有 `hard/*` 的 `expectations.json` 记录的是「造样本时声明的构造意图」。**因此覆盖率的提升（580 → 1390）与发现能力并不相关——本轮 2 项缺陷全部来自第 1 次运行的 7 例，而不是来自那 1383 例。**

一句话概括本轮的根因形状：**第二轮的问题是「判定没有牙齿」，第三轮剩下的是「判定没长在交付路径上」「证据没有自证」，以及「真值取自产物自身的腿根本看不见结构损失」。**

## 2. 解析层（S1）

### 2.1 N1 页眉页脚：采集清单是「部件枚举表」，不是「可见内容契约」

- 事实：`doc2md/pipeline/s1_parse.py:19` 的模块文档把 DOCX 采集范围逐部件列出（正文、脚注 `word/footnotes.xml`、尾注 `word/endnotes.xml`、编号、样式），页眉页脚部件不在清单内；全仓 `grep sectPr / w:header / w:ftr / headerReference` 在 `doc2md/` 下 **0 命中**——不是被过滤，是从未解析。
- 实测：TC-M2-08 在含 `w:headerReference` 的文档上得 `header_hits=0 footer_hits=0 warnings=[] blocks=2`。
- 根因泛化：**「未采集」与「采到了但降维」在现有模型里不是同一件事**。降维有账本（`W1043` 分片、`W1044` 降级、`W1045` 表格拍平、`W1046` 旋转/RTL），未采集没有——因为告警码的语义前提是「S1 知道有这个东西」。当采集边界由部件枚举表定义时，表外的内容对解析器不可见，自然不可能产生告警。
- 后果：用户按「Word 里能看见的都在 MD 里」理解就会静默丢内容，且**产物侧完全无法自证丢失**（`ir.json` 与 `report.html` 都无提示）。这是本轮唯一「高」等级项。
- 与第二轮的关系：这是根因 R3（有损结构缺少降维账本）的**扩大型**——第二轮补的是「降维要入账」（D5 已闭合），本轮暴露的是「未采集根本不入视野」。

### 2.2 特征保留：D7 的 run 顺序根因已闭合，但「元数据优先」仍未成为分层策略

- 事实：第二轮 D7 的 14pt 提示框晋升标题，根因是段内 run 乱序导致字号取样不稳定；本轮 TC-M2-06 换序后行字号恒 `10.0`，TC-M5-01 三段均判 `paragraph`——已闭合。
- 残余：DOCX 的显式语义（`w:pStyle` 的 Heading 样式、`w:numPr` 的真实列表）仍不作为**强信号优先**，只作启发式的一个输入。这在上轮记为 R2「单特征判定」，本轮把标题侧的取样缺陷修掉了，但没有把「元数据优先、几何/字体启发式兜底」写成分层规则。
- 真值现状（本轮复核更正，见 5.4）：**独立真值已经存在**——`tests/corpus/ideal/` 有 11 份 DOCX（111 标题）与 10 份 PDF（102 标题）标注，由 `make_ideal_docx.py`（python-docx 直读源 XML 样式）与 `make_ideal_pdf.py`（pdfplumber 逐行字号 + 生成器字号约定）从**源文件**导出，不经管线任何环节；`tests/test_qa_n03_ideal.py` 以 46 项断言钉住「标注与源一致」+「S3 对 DOCX/PDF 的 F1 == 1.0」（`pdf_10` 要求 pred 为空集）。缺的不是这份真值，而是**语料之外真实 PDF 的人工标注**，因此「启发式在真实文档上准不准」仍无法自证 → B-35 重新定界（见 5.4）。

### 2.3 HD-1 跨页表格整列脱落：行装配按文本流顺序，不按几何

- 事实：`tests/corpus/hard/hard_02_cross_page_table.pdf` 声明 1 张 3 列 × ≥41 行（表头 `序号 / 科目 / 金额`）。实测产物 `table[0]` = 2 列 × 37 行（表头只剩 `序号/科目`）+ `table[1]` = 3 列 × 5 行（第 2 页残余、表头重复），`金额` 列的内容以 `金额10011002…1036` 形式落在正文段落里；`ir.warnings` **0 条**。
- 根因形态：S1 的 PDF 行装配以 pdfminer 文本流的读取顺序为序，列归属由「同一行内的 token 相邻」推断。跨页时第 2 页的首行不带表头，列数判定与第 1 页不一致，于是「续表」被判成另一张表，而脱落的那一列在两段之间失去了配对对象，被降级成正文。
- 泛化：**几何信息（y 坐标、x 分栏位）已经在 `RawPage` 里，但行装配没有以它为主判据**。这与 2.2 里 D7 的教训同构——第二轮修的是「段内 run 顺序决定字号取样」，本轮栽在「文本流顺序决定列归属」，两者都是**把遍历顺序当成了语义顺序**。
- 为什么无声：现有降维账本只在 S1 明确识别到「合并/嵌套」这类结构时挂 `W1045`；列配对失败后该列不再存在于任何表格对象里，告警的判定入口本身被绕开。这暴露了 3.3 的说法错误（见该节的更正）：账本覆盖的是「S1 建模到的结构」，不是「源文档里的结构」。
- 受限与出口：改判据（按 y 聚类 + x 分栏位定列）后，「哪一列对应哪个表头」只能靠人工逐页对照真实 PDF 确认，且必动产物字节 → B-43；难度样本结构断言转绿 + 22 篇语料与 320 页金样本逐字节人工复核 + `PIPELINE_VERSION` 契约级升位是出口条件。

### 2.4 HD-2 目录页误判 + run 间空格丢失：两个独立缺陷叠加后仍然无声

- 事实：`hard_05_leader_dots.pdf` 声明产物应含 `第一章 总则` / `第二章 职责` / `第三章 附则`。实测三者全部缺失，产物为 `| 第一章总则 | .................... | 1 |`；`ir.warnings` **0 条**。
- 三个可分立的子缺陷：① 点线引导符被当作一个独立单元格；② 整页目录被识别成表格（它没有边框，与 2.5 的 D01 无边框表恰好是同一个判据的两难——D01 要求「无边框也要成表」，D05 要求「无边框的目录不成表」，区分只能落在**引导符密度 + 页码右对齐 + 行数形态**这三类特征上，而这三类阈值当前都不存在）；③ run 之间的空格丢失，使 `第一章 总则` 塌成 `第一章总则`。
- 根因形态：①② 属结构判定的**特征缺失**（同一几何线索在两类文档上要求相反结论，却只有一条规则）；③ 属文本保真的**字符级损失**，与前两者无关，是独立缺陷——它单独就足以破坏检索面（用户搜「第一章 总则」搜不到）。
- 泛化：**「误判成表」与「误判不成表」必须一起调**，任何只修 D05 方向而不回归 D01 的改动都会把另一条难度样本推红。这也是为什么本册把 D01 与 D05 记在同一条根因链上（2.3/2.4 与 B-43/B-44 必须同批），而不是当成两个独立待办。
- 受限与出口：三类阈值的可误判面需人工在真实目录页上确认（正文里的点线填空不能被误判成目录）→ B-44，与 B-43 同批重烤。

## 3. 映射与门禁层（S1.5 / S2 / S3）

### 3.1 N2 开关与非交付分支：默认档不读的那个键

- 事实：`doc2md/pipeline/s1_5_gate.py:236-253` 的 `finish()` 里，`reject_on_any` 只在 `else`（即 `mode != "auto"`）分支被消费；`auto` 分支用的是另外三条独立规则（连续坏页成段 ≥ `bad_run_min`、总页数 ≥20 时空页占比 > `bad_ratio_max`、全页皆空）。默认配置 `mode = auto`。
- 实测：TC-M3-02 同一夹具在 `reject_on_any_bad_page` = true / false 下得 `auto_on=(True,[])` 与 `auto_off=(True,[])`，完全相同；切到 `even5` 档后 true 才拒收（`page 1: chars=37 < 120`）。
- 根因泛化：**「配置键存在」与「配置键在默认路径上被读」是两个独立事实，现有机制只在非默认分支上验证后者**。CH-424 把 auto 改成 run/ratio/all_pages 三条判据时，`reject_on_any` 就成了没人读的孤儿键，而 `docs/dev-plan.md` 还把它描述成 auto 的总开关——判定改造与配置描述分属两次改动，中间没有「默认档必须消费每个声明键」的红线。本轮已把文档口径按实况改正（§892），但键的存废属契约变更（接上等于把默认档改成「单页坏即整篇拒」），需真实语料误拒率 → B-32。
- 同族历史缺陷：这与其说是新问题是旧根因 R4（出口契约不统一）的镜像——R4 是「同一参数在不同出口有几种语义」，这里是「同一个键在不同档位有几种效力」。

### 3.2 可判定性正向改进：门禁缺页即抛

- `finish()` 开头对 `self._need` 与 `self.metrics` 求差，缺页直接抛 `gate: N decision/report page(s) never fed`（含首个缺页页号）。这是「判定层拒绝在证据不全时给出结论」的正确形态，本轮据此确认 S1.5 不会静默产出「采样不全的通过」。

### 3.3 有损结构模型：降维账本已到位，但**入账范围被本轮证伪过一次**

- 表格：`gridSpan`/`vMerge` 与嵌套表拍平已入 `W1045` 账本（TC-M5-06 实测 `warnings=['W1045']`，D5 闭合）；跨片表不重复合并实测 `counts=1/1/1 tables=3`。
- 分页：段内 `\x0c` 已按 run 位置切分，TC-M5-07 实测 `seq=['paragraph','page_break','paragraph','paragraph'] pb_at=1`（D6 闭合）。
- 仍属既定边界（ADR，不记为缺陷）：块级链接至多一条、无法表达行内多处链接（O-11）。GFM 不支持合并/嵌套表，降维本身是合理取舍。
- **本轮更正（收口改判的第二处）**：首稿在本节写过「问题只在账本完整性，而账本本轮已补齐到『凡 S1 可见者均入账』」。D02 直接反证——整整一列脱落、`warnings` 0 条。准确的表述是 **「凡 S1 建模到的结构均入账」**：告警入口挂在「已识别为表格/已识别为合并」的对象上，因此一旦列配对失败、内容被降级成正文段落，就离开了账本的视野。这不是账本没写完，是**入账判据挂在结果对象而非源结构上**，属 G1 的同构复现（G1 说「表外内容对解析器不可见」，这里是「配对失败的内容对告警器不可见」）。
- 因此 B-43 / B-44 的出口条件除「结构断言转绿」外还必须包含一条：**列丢失与目录误判要能在 `ir.warnings` 里显形**，否则修完判据仍会留下下一个无声缺口。

## 4. 生成层（S4 / 打包）

### 4.1 转义有实现、无单一来源

- 事实：转义职责分散在三处——
  - S1 DOCX 单元格预转义：`s1_parse.py:1108-1113`，`& → &amp;`、`< → &lt;`、`> → &gt;`；
  - S3 表格单元格：`s3_structure.py:550-559` 的 `cell_md`，按硬编码 (a, b) 逐对 `replace`，转义 `<` 但**不转义 `&`**；
  - S4 行内/行首：`s4_render.py:77-105` 的 `_escape_inline`（`_INLINE_ESCAPE_TABLE` 翻译表）+ 四条行首正则。
- 实测（P09 / TC-M6-12）：同一篇文档正文里的 `&` 走 `_escape_text`、表格单元格里的 `&` 不走；DOCX 单元格因 S1 已预转义，`cell_md` 再把 `&amp;` 转成 `&amp;amp;`——字面 `a&amp;b` 输出 `a&amp;amp;b`（与 `| A &amp; B |` 的表格展示同口径，本轮确认这是**一致但双源**的行为）。
- 根因泛化：**同一套「源文本 → Markdown 字面量」的规则被写了三遍，且没有交叉断言钉住等价性**。第二轮 D2/D3/D4 的修复是「在每一处补上转义」，形态上必然产生多源；只要新增一个出口（例如 report.html 内嵌正文），就会再复制第四遍。R1 当年记为「字面/语法没有分层」，本轮的残余是「分层了，但每层各自实现」。
- 为什么没继续改：任一侧改动都动产物字节，需黄金重烤与含 `&`/`<` 表格样本的人工比对 → B-37，并与 B-33 同批以摊薄重烤成本。

### 4.2 红线是「标记字符串」检查，不是结构回读

- 事实：`s4_render.py:215-227` 的 `_contract_violation` 只扫 `_ANCHOR_MARK`（`](#`、`#page-`）与 `~~`；本轮已把它接进生产路径逐块调用（`render(..., contract=True)`，CH-500 / R17-PIPE-2），并豁免代码块（围栏内容由 `_code_fence` 决定）。TC-M6-02 与 V-PIPE-11b 实测：违规时 `E5031 detail={'reason':'render_contract','marker':'<script','block_type':'table'}`，代码块 `len=34` 不误杀。
- 泛化的不足：红线能抓住「已知漏网标记」，抓不住「未知的新语法激活面」（例如单元格 `&` 双源这类分叉，靠字符串扫描永远不可见）。缺的是**结构级回读校验**（把产物用同一 Markdown 解析器读回，比较块类型/列数/HTML 白名单），而不是更多标记常量。
- 收益判断：这一层是 D2/D3/D4 类问题的最后一道闸；补回读校验不需要改产物字节，属可本机自证项，已排入优化方案。

### 4.3 产物字节冻结：既是防线也是改进税

- 观察：本轮五个挂起的决策（B-33 页眉页脚、B-37 转义单源、B-42 无候选探活、B-43 行装配判据、B-44 目录阈值）被挂住的直接原因里都有同一条——**改动必然改变 `report.html` 或 `content.md` 的字节**，需要重烤 22 篇语料黄金并人工复核。黄金字节冻结是正确的回归防线，但当告警码、转义口径、LLM 统计、S1 行装配、目录识别五个互不相干的决策都堵在同一道重烤上时，它就从防线变成了排队口。B-43/B-44 还多一层：重烤之后必须**人工逐页对照源 PDF** 才知道改对没有，光看绿不算。
- 处置方向（见优化方案）：把「产物成员结构」与「产物字节」分开验——成员集合、版本戳、schema 一致性用**结构断言**（X-10/X-11 已有雏形：`bytes=661 zip_md=661`、三成员清单），内容差异用**diff 白名单**（只允许新增告警行/转义列），避免每次重烤都全量人工比对。

## 5. 校验 / 契约 / 度量层

### 5.1 N3 契约可达性：探活路径与输入分布耦合

- 事实链：`llm.py:606` 的 `_candidate_indices()` 判无候选 → `payload_batches()`（`llm.py:784-790`）返回 `[]` → `repair()` 的 `for payload in payloads`（`llm.py:691-700`）**一次都不执行** → 不发 HTTP、不抛 `LlmServiceError` → `convert.py:333-344` 的 `except` 分支不可达 → `fallback=false` 也回 rc=0，报告记 `source=server` / `batches=0`。
- 实测：TC-M7-04 在本机 22 篇语料上全部 0 候选，`rc=0 status=ok`；只有自建粘连段落文档才复现 E5041/rc=4（TC-M7-03）。
- 根因泛化：**「错误码可达」不等于「契约在所有输入域可达」**。`llm.mode=server + fallback=false` 想表达的契约是「服务不可用必须当场可见」，但它被实现成「请求失败时可见」；当某类输入根本不产生请求时，契约静默失效。这类缺陷在测试上的表现是「构造不出来」，在本轮之前被误记为「未构造成功」，实际是产品侧的条件可达。
- 检查项（可复用）：任何以「失败可见性」为内容的契约，都要枚举**触发路径的输入域**，并为未触达路径显式命名（`source=server-untouched`、`probe=not-run`），否则运维无法区分「服务健康」与「服务从未接触」。
- 为什么没继续改：两种改法都要写进 `llm_stats`，而 `llm_stats` 进 `report.html` → 产物字节变化 + 黄金重烤；且「无候选算不算服务失败」本身是产品决策 → B-42。

G6 需要特别说明其**普遍性**：本轮 111 项探针（49 + 32 + 30）里，有 4 项首跑给出的「通过」或「失败」都是假信号（3.6%），另有 4 处**结论前提未回对象本身复核**——O-e 是对《审查》的一条前提、O-f 是对本册自己的分档判据、O-g 是对自动骨架的断言面、O-h 是对自己上午那份覆盖率日志的 TOTAL 行。后四处都发生在收口对账时才被抓到，性质比前四处更严重：O-e 已被写进《审查》与 QA 文档并成为一条 B 项的依据，O-f 直接产出了一份错误的发布判定，O-h 则证明**继承可以只隔半天、对象可以是自己刚写的数字**（90% 与 91% 的差只是 .5 取整边界，档位没变，但四处文档都跟着错了半天）。四类探针假信号的共同形态不是「测试太松」，而是**判定式里含有一个让断言在「没测到东西」时也成立的前件**（`if len(ids) >= 2`、`rc == 0`、子串包含、常量表参与清单、骨架只读声明字段的一半）。这类缺陷在功能测试上表现为「全绿但没保底」，在产品上表现为「契约静默失效」（G3 的同构），在文档上表现为「结论看起来有据、实际来源没被打开看过」（O-e / O-f）。因此本轮把它写成红线，而不只是修 4 个用例：

- 任何「数量足够才继续」的判定必须补一条「不足即判失败」；
- 任何「结构存在性」判断不得用子串，须用可区分转义状态的解析或正则；
- 任何跨面一致性校验必须先声明分母，再做集合双向差；
- 任何参与清单的计时项必须有非负与基准一致的断言，否则显式标注为伪阶段并从占比中排除；
- 任何写成 B 项/偏差的结论，其前提必须附**文件路径 + 打开看到的原文**；继承上一轮结论时，须标为「待复核」而不是「已核实」；
- **新增**：任何自动生成的测试骨架，其断言必须覆盖声明字段全集；未覆盖的字段一律显式 fail，不得用 `pytest.skip("TODO")` 出现在会被收集的路径上；
- **新增**：缺口 / 失败的分档只看「行为是否与既有承诺矛盾」，不看修复成本与修复所需环境；「需要人工或外部确认」不是降级理由。
- **新增**：任何会被取整的指标（覆盖率、通过率、占比），引用时须同时给出**分母 + 精确值 + 打出值**，且每次收口回读产生它的那份日志的 `TOTAL` 行，不得沿用上一次的显示整数。

## 8. 影响排序

按「语义破坏 × 触发概率 × 下游放大 × 是否阻塞发布决策」排序（收口改判后重排：前两位是本轮新增的**缺陷**，按 2.2「P0 失败即阻断发布」必须置顶）：

1. **HD-1 / G8（高，阻断发布）**：跨页表格整列脱落 + 裂成两张，`warnings` 0 条。数字/财务类文档的头号风险形态——**表格还在，但那一列的数字不见了，而且没人报错**。→ B-43，须逐页人工对照真实 PDF 定列归属判据。
2. **HD-2 / G8（高，阻断发布）**：目录引导符成单元格 + 整页误判为表 + run 间空格丢失使 `第一章 总则` 塌成 `第一章总则`；后者单独就破坏检索面。→ B-44，与 B-43 同批（D01 无边框表要求「无边框也成表」、D05 目录要求「无边框不成表」，同一判据的两难必须一起调）。
3. **N1 / G1（高）**：内容静默不可见，产物侧无自证；触发条件是文档含页眉页脚（Word 里极常见）。→ B-33，需 ADR + `W1047` 决策。
4. **G6 / G9（中，面广）**：不改变任何一篇产物，但决定下一轮判断质量；本轮 4/111 探针首跑为假信号，另有 4 处结论未回对象本身复核（O-e 前提、O-f 分档、O-g 骨架断言面）。G9 是同一层的结构性结论：**1390 项 + 580 项 + 22/22 语料对 D02/D05 全绿，7 例独立真值第一次跑即 2 红**——覆盖面与发现能力不相关。→ B-34 解除依赖、可本机自证；B-35 收窄为「真实 PDF 的人工标注」；B-46 把结构断言送入门禁。
5. **N2 / G2（中）**：配置面上的假开关；用户以为设了防护，实际默认档无效。文档口径已改，键的存废需外部语料 → B-32。
6. **N3 / G3（中）**：`fallback=false` 的失败可见性对零候选文档失效；只影响开了 server 模式且文档无候选块的运维场景 → B-42。
7. **G4 / 4.2（中低，安全相关）**：转义多源与红线口径窄；本轮实测未产生产物层语义破坏（O-b 为探针误判），但缺少结构回读校验意味着新语法面只能靠语料发现。→ B-37，与 B-33 同批重烤。
8. **G5（中低，工程效率）**：改进税；不阻塞当前版本，但会让下一轮所有产物面改动排队——本轮 B-43/B-44 恰好被它挂在后面。→ 结构断言 + diff 白名单。
9. **N4 / B-45（中低）**：中文序号层级口径两侧自洽、无红线；属真值侧裁定，不是实现错误。
10. **G7（低，但有越权面风险敞口）**：`perms.py` 覆盖 40%。→ 本轮已列入优化方案 P2，可本机自证。
11. **性能（无缺陷，有明确杠杆）**：S1 占单篇 **97.4%**（两轮独立复证 12.7 s / 10.43 s 量级；320 页墙钟 9.998 s、峰值 RSS 236.8 MB，1 页 0.158 s / 59.7 MB），S1.5/S2/S3/S4/打包为噪声级（0.024 / 0.148 / 0.11 / 0.055 / 0.083 s）。页区间并行两轮 1.78×–2.64×（首轮 1.61×–2.79×）且 `lines=15613` / `pages=320` 逐字节一致，`read_pdf` 内层耗时相加 ≈ 单段墙钟——**加速来自并行展开而非少算活**。API 窗口实测 `limit=500` 324,038 B / 0.045 s vs `limit=20` 16,940 B / 0.002 s（体积 19.1×）。结论不变：优化 S2–S4 任何一处都不构成性能改进，唯一大杠杆是 B-38（须先证分段与整篇逐字节等价），其次 B-39。
