## 1. 影响等级与偏差类型

| 等级 | 判定标准 | 处置口径 |
| --- | --- | --- |
| **高** | 破坏正文语义/文档结构，把源文档里不存在的字符带入交付正文，或把不可信内容带入下游渲染面；用户可感知「内容看不见」或「内容多了」 | 阻断发布，P0 立即修复或产品决策 |
| **中** | 常见场景下结构或契约错误，调用方会误判 | 发布前修复或书面豁免 |
| **中低** | 边界路径错误，影响可感知但范围有限 | 与相关修复同批处理 |
| **低** | 可观测性、文档、结果行展示或度量口径问题，不影响转换结果 | 登记后排期 |

偏差类型沿用任务口径：**功能缺失、逻辑错误、结构或格式差异、兼容性与性能问题**。安全类问题归入「结构或格式差异」并标注安全影响。

本册按四组分列，判据始终是《测试文档》2.1 那一条——**行为是否与既有承诺矛盾**，不看修复成本，也不看是否需要人工/外部样本：

- 第 2 节 **契约缺陷**：实际行为违背既有承诺（含「静默」这一加重情节）。
- 第 3 节 **缺口**：行为与当前文档口径一致，缺的是能力或未裁定的契约决策。
- 第 4 节 **文档精度偏差**：代码是对的，文档写错了——这类不改代码，只改文档，但必须逐条留痕，否则下一轮会把错文档当真值继续复验。
- 第 5 节 **观察项**：探针/度量/登记层面的自纠，多数不改变用例状态，但决定下一轮的判断质量。

## 4. 文档精度偏差（代码对、文档错；只改文档，逐条留痕）

这六项全部在附录 C（HTTP 契约表）与 `errors.py`/`api.py` 实测响应体之间。它们的共同形态是**文档承诺了一个不可达的形态**——调用方按文档写客户端会拿到与文档不同的字节。本组不改代码（改代码会动产物/契约字节，需重烤黄金），只把文档改成实测形态；每项都给出实测证据。

| ID | 文档位置 | 文档写法 | 实测形态 | 偏差类型 | 影响等级 | 处置 |
| --- | --- | --- | --- | --- | --- | --- |
| C-1 | 附录 C `POST /jobs` 错误列 | 「**409 `E4091`** 库内已有编辑且未 `force`」 | HTTP **409 在整个 API 面上不可达**：E4091 的两条抛出路径（`api.py:518` 预检、`api.py:582`/`:687` 竞态）都被就地捕获并折进 **202** 的逐文件信封 `{"status":"conflict","code":"E4091","edited_blocks":N}`；E4092 只作为作业码字符串出现在 `worker.py:330`，从不作为 `ApiError` 抛出。实测 `second=202/conflict/E4091 edited_blocks=1`（TC-M10-13） | **结构或格式差异**（文档自相矛盾：同一行的成功列已写「逐文件状态可为 `conflict`」） | 中 | 附录 C 错误列删去 `409`，改为「202 逐文件 `conflict` + `E4091`；HTTP 409 段位当前不可达」 |
| C-2 | 附录 C `DELETE /docs/<doc_id>` 成功列 | 「200 `{...counts, cascade}`」 | 顶层键实测为 `['deleted','doc_id','files']`，**无 `cascade` 键**；`cascade` 只出现在 `GET /audit/deletions` 的**逐行**里（`row_cascade=['deleted','files']`）。实测 TC-M10-29 | **结构或格式差异** | 中低 | 改为「200 `{doc_id, deleted:{audit,blocks,events}, files:[...]}`；`cascade` 为审计行字段，不在本端点」 |
| C-3 | 附录 C `POST /jobs` 成功列 | 「逐文件状态可为 **`ok`** / `conflict` / `rejected` / `error` / `attached` / `idempotency_hit`」 | 同步成功路径新建的 job dict **不含 `status` 键**，故 `ok` 永不出现；`idempotency_hit` 也不是 `status` 的取值，而是**并列的布尔键**（`status` 为 `"done"`）。实测 TC-M10-13 `forced=202/None`、TC-M10-14 的真值表 | **结构或格式差异**（枚举列了不可达取值） | 中低 | 把 `ok` 与 `idempotency_hit` 从 `status` 枚举里移出，分别注明「成功项无 `status` 键」与「幂等命中是并列布尔键」 |
| C-4 | 附录 A / `errors.py::to_body` 契约描述 | 错误响应体含 `code`/`message`/`detail` 三键 | `to_body` 在 `detail` 为空时**省略该键**，故 404 体实测为 `{code,message}` 两键 | **结构或格式差异** | 低 | 注明「`detail` 为空时省略」；调用方不得假定三键恒在 |
| C-5 | 幂等重放语义描述 | 未写明重放响应的形态 | 重放命中返回 `status="done"` + 并列 `idempotency_hit=true`，**不重跑转换**；与首次响应的 `status` 缺省形态不同 | **结构或格式差异** | 低 | 附录 C 补一行「幂等重放：`status="done"` + `idempotency_hit=true`」 |
| C-6 | dev-plan 批量入口「全或无」表述 | 目录批量遇到不支持类型即整批 415 拒绝 | 需加扩展名过滤caveat：目录内的 `.txt` 等**非受支持扩展名被静默忽略**（`api.py:421-428`，与 CLI 同口径），只有「扩展名受支持但 magic 不符」的文件才触发整批 415 | **功能缺失**（文档过度声明） | 中低 | 「全或无」后补「（仅对受支持扩展名；其余按 CLI 同口径静默忽略）」 |

C-1 是本组唯一等级为「中」的项：409 是调用方**会据此写重试逻辑**的状态码，文档承诺一个不可达的 409 等于让客户端留一段永不执行的分支，同时把真实需要处理的 202/`conflict` 漏掉。

## 7. 结论

1. **核心面 127 例零失败**（126 通过 / 1 缺口 / 0 失败，口径 C = 99.21%）。第三轮的 13 项 API 契约偏差、CH-500/CH-503 的修复全部复验通过。
2. **本轮抓出并闭合一项高级别契约缺陷（D-1）**，且它是**通用 DOCX 缺陷**而非 `.doc` 专属——影响面覆盖所有 LibreOffice 写出的 DOCX。闭合链路完整：根因（`marker()` 对空 `lvlText` 兜底成 `"%1."` 且不检查 `numFmt="none"`）→ 修复（计数器推进保留在守卫之上，使深层 `%2` 引用仍算得对）→ 红线（4 项 gate）→ 三次变异证明（M-N1 去掉整条守卫转红 2 项；M-N2 只留 `numFmt` 半条转红 1 项，证明两半独立把守；M-N3 恢复 `return marker or f"{counters[ilvl]}."` 仍全绿，如实记为**装饰性死代码清理、非承重**）→ 全量无回归（门禁 683/0、全量 1516/0、覆盖率 7843/737、语料 22/22、`ideal` 指标与 `evaluate` 宏观指标逐项不变）。
3. **发布判定不变：阻断**。D-2 / D-3 与第三轮同两条，B-43 / B-44 未闭合前不得发布，或由人工逐页对照真实 PDF 复核后出具书面豁免。
4. **文档精度偏差 6 项须在收口同批改掉**（第 4 节）。它们不改代码，但若不改文档，下一轮会拿错的契约当真值继续复验——C-1（不可达的 409）尤其会让调用方漏掉真实需要处理的 202/`conflict` 分支。
5. **下一轮的真值面短板已定位**：D-1 之所以能躲过全部既有腿，是因为 22 篇语料的 DOCX 都由 python-docx 写出，编号形态单一。**补一条「LibreOffice 写出的 DOCX」语料**（含样式级 `numPr`、`numFmt="none"`、空 `lvlText` 三种形态）比再加十条 python-docx 语料更能防同类缺陷；此项本机可做，已列入《优化方案》。
