## 1. 结论先行

### 1.1 本轮最重要的一条判断

**四项开放缺口全部集中在「需人工裁定或需外部样本」这一类，而本轮唯一新发现的真缺陷（R19-PIPE-3）出在一条被上一轮判成「需外部样本」的路径上。**

这两件事合起来指向同一个根因：**真值面的形状决定了能看见什么缺陷**。22 篇语料的 DOCX 全部由 python-docx 写出，编号形态单一（要么无 `numPr`，要么显式 decimal/bullet），于是「样式级 `numPr` 指向 `numFmt="none"`」这一 LibreOffice 恒定形态在四条既有腿上门禁 679 项 / 全量 1512 项 / 语料 22/22 / `ideal` 21 篇全绿。缺陷不是被漏测，是**语料里不存在这个形状**。

第三轮把 legacy `.doc` 记成「需外部样本」的缺口，本轮改判为可执行（本机 LibreOffice 就能造真实 OLE 夹具），第一次跑就命中。这不是运气——`.doc` → `.docx` 中间件必然由 LibreOffice 写出，因此必然带那个形状。**改判的价值不在多了一条用例，在于把一种此前不存在的文档形状引进了真值面。**

### 1.3 与第三轮的根因对照

第三轮的头号根因是「四条腿的真值都取自管线自身已认可的形态」（自证循环）。本轮该结论**被再次证实，且被具体化**：D-1 躲过的正是那四条腿，而抓住它的是第五条腿（本机 LibreOffice 造形状）。因此第三轮的处方「补独立真值面」是对的，但**独立真值面的价值不在数量，在形状覆盖**——再加十条 python-docx 语料也抓不到 D-1。

## 2. 解析层（S1）

### 2.1 D-1 / R19-PIPE-3：规范三态被压成两态

**病灶**：`doc2md/pipeline/s1_parse.py::_DocxNumbering.marker`。

ECMA-376 §17.9.19（`ST_NumberFormat`）对「该级不显示编号」给了两种表达：`w:numFmt val="none"`，以及空 `w:lvlText`。加上「`w:lvlText` 元素缺失」这一畸形文档形态，一共是**三态**：

| 形态 | 规范语义 | 修复前实现读到 | 修复前实现产出 |
| --- | --- | --- | --- |
| `numFmt="none"` | 本级不显示编号 | `fmt="none"`（**从不检查**） | 继续走 `%1.` 兜底 → 伪造 `1. ` |
| `lvlText` 存在但为空 | 本级不显示任何内容 | `text=""` | `cfg["text"] or "%1."` → 兜底成 `%1.` → 伪造 `1. ` |
| `lvlText` 元素缺失 | 畸形文档，应保守兜底 | `text=""`（与上一行**同值**） | 兜底 decimal（这一态的兜底是对的） |

第 2、3 行在读出来的数据上**不可区分**——都是 `""`。于是「不显示」被当成「畸形」，兜底逻辑把文档里不存在的字符写进了交付正文。

**为什么静默**：这条路径不经过任何降维/告警账本。`W1045`（表格降维）、`W1043/W1044`（跨片表格/未缝合）、`W1046`（旋转/RTL）都是「结构被改写时入账」，而**「文本被增加」不在任何账本的语义范围内**。`warnings` 因此为 `[]`——不是漏报，是这类损伤没有对应的码。

**修复的三处与它们的分工**：

1. 级别字典增记 `has_text`（`txt is not None`），把三态还原成三态。这是**根因修复**：没有这一位，第 2、3 行永远不可区分。
2. `marker()` 增守卫 `if cfg["fmt"] == "none" or (cfg["has_text"] and not cfg["text"]): return "", -1`。**守卫刻意放在计数器推进之后**——深层级的 `%2` 之类引用仍要算得对，只是本级不产出标记。放反了会让「第 2 级显示、第 1 级不显示」的文档算错编号。
3. 删掉 `return marker or f"{counters[ilvl]}.", ilvl` 的兜底。变异证明 M-N3 显示这一处**不承重**（恢复后 4 项全绿、门禁 683 全绿），属装饰性死代码清理——如实记录，不冒充修复。

`("", -1)` 不是新发明的哨兵：`if not nid or nid == "0"` 与 `if not cfg` 两条既有分支已经返回它，消费侧（`_docx_para` 的 `marker, list_level = "", -1` 缺省）本来就要处理。修复因此不引入新契约。

**通用性**：这是**通用 DOCX 缺陷**，不是 `.doc` 专属。LibreOffice 写出的 `Heading1..9` 样式一律挂样式级 `w:pPr/w:numPr → numId=1`，而 `numId=1 → abstractNumId=1` 的九级全是 `numFmt="none"` + 空 `lvlText`。任何经 LibreOffice 写出或转换的 DOCX 都命中。

**红线形态**：`tests/test_ch504_numbering.py` 4 项（全 gate）。第 4 项是**反向守卫**——真实 decimal 多级编号（`%1.` / `%1.%2.`）必须仍产出 `["1.", "1.1.", "1.2."]`、层级 `[0,1,1]`。没有这一项，「一律返回空」也能让前三项全绿。

### 2.2 B-44 的塌词半：单元格装配把词内空格删了

**病灶**：`doc2md/pipeline/s1_parse.py::_row_cells`。

两处叠加：

- 入口过滤 `cs = [c for c in chars if (c.get("text") or "").strip()]`——把纯空白字符**整颗丢掉**，不是保留后参与聚类。
- 出口拼装 `return ["".join(seg).strip() for seg in cells]`——**无分隔符**连接。

于是 `第一章 总则` 中那颗空格字符被丢掉后，两侧字符直接相接成 `第一章总则`。实测影响面：**220 行 PDF 表格行中 17 行**受影响，分布在 `hard_05_leader_dots`、`hard_08_header_variants`（8 行）、`pdf_10_two_column_6p`（6 行）。

**格式不一致的加重情节**：DOCX 路径的单元格文本**保留**空格（`_docx` 侧按 `w:t` 拼接，含 `xml:space` 语义），只有 PDF 路径删。同一份内容两种来源产出两种字节，属「同一语义两条实现」的典型分叉。

**这一半不需要人工裁定**：B-44 的登记里已明写「其中『run 间空格保真』一条不依赖人工裁定，可单独实施（仍随批次重烤）」。它至今未实施的原因是**产物字节冻结税**——改它会动 PDF 表格单元格字节，必须与 22 篇语料黄金重烤同批，而重烤需要人工逐篇复核。

### 2.3 B-43 跨页表格：行装配按文本流顺序，不按几何

第三轮已归纳，本轮原样复现，根因不变（方案侧记为 G8）：S1 的行装配信任 pdfminer 的文本流顺序，而不是按 y 坐标聚类。跨页续表的第 2 页残余因此成为独立表（表头重复），而 `金额` 列在流序里与主体脱开，整体脱落成正文一长串 `金额10011002…1036`。

**为什么无声**：与 D-1 同型但方向相反——D-1 是「凭空增字」，B-43 是「列归属丢失 + 裂表」。后者本该由 `W1045`（表格降维入账）覆盖，但 `W1045` 的触发点是**合并单元格拍平**（`gridSpan`/`vMerge`），不是**列脱落**。账本存在，入账范围没覆盖到这种降维。第三轮已把这一点记为「入账范围被证伪过一次」，本轮维持该判断。

### 2.4 采集面：B-33 页眉页脚仍是「部件枚举表」而非「可见内容契约」

本轮**剔除面已证正确**：`hard_08_header_variants.pdf` 的 `奇数页`/`偶数页` 与孤立页码 `- N -` 零残留（TC-HD-08 两条 `absent` PASS，TC-M5-12 独立复证）。

**采集面仍缺**：S1 的 DOCX 分支从不读 `word/header*.xml` / `footer*.xml`，`W1047` 未立（附录 D 仍是预留位，告警分母维持 4）。用户可感知形态是「看不见的内容没了，且没有任何提示」。这不是实现疏漏，是**产品决策未做**：页眉页脚并入正文还是逐页附注，属 ADR 级问题。

### 2.5 R19-PERF-2：双栏路径上的二次复杂度（登记未实施）

`doc2md/pipeline/s1_parse.py::_blanks_in_band` 与同文件内嵌的 `keep()` 在双栏路径上对同一字符带重复扫描，实测量级 **32.9×–323×**。

**不实施的理由是排序判断，不是难度**：① 收益 <1% 墙钟（S1 占约 97%，但双栏路径只在 `pdf_10_two_column_6p` 一类文档上走到）；② 风险集中在双栏路径；③ 该路径**只有一个语料 oracle**，改坏了很难被发现。建议与 B-44 的单元格空格修复**同批**做——两者都动 `s1_parse` 的 PDF 侧、都要重烤黄金，合并批次能把重烤成本摊薄。

### 2.6 R19-PIPE-2 残留：显式代码块内的链接被吞且无声

链接提取在显式 `fence`/`indent` 块内仍会被吸收，产物 `links=[]`、`warnings=[]`。

**不实施的理由是缺 oracle**：31 份夹具里该形态**零出现**。要修就得先造夹具、再定新 W 码、再进附录 D 预留位、再补 trace 的 W 覆盖率测试——四步里没有一步能在本机自证「这个 W 码该不该存在」，属产品决策。

## 3. 映射与门禁层（S1.5 / S2 / S3）

### 3.1 B-45：CJK 序号→层级映射没有任何红线钉住

**病灶**：`doc2md/pipeline/s3_structure.py::_level_from_number` 内的局部字典 `order = {"章":1,"编":1,"部":1,"篇":1,"节":2,"条":3,"项":4}`。

`hard_08` 的 `第 N 节 正文章节标题` 因此判 H2，而生成器声明 H1。两种口径各自自洽（公文惯例「节从属于章」→ H2；「每页首行 + 显著大字号即章级」→ H1），**且该映射当前没有任何 gate 红线钉住**——改哪一侧都会动 `content.md` 字节，却没有任何测试会因为改错方向而转红。

这是本层最危险的形态：**一个决定产物字节的常量表，处在零测试覆盖状态**。它没被记成缺陷，是因为行为与文档口径一致（文档确实写了「节→2」）；但它必须与裁定同批补上红线，否则裁定结果本身无法被保护。

### 3.2 D-3 的目录误判半：`ln.row` 反向封锁标题晋升

**病灶**：`doc2md/pipeline/s3_structure.py::analyze` 主循环内的 `if ln.row: lvl = None`（CH-485 / R9-PIPE-4 引入，目的是不让表格首列的 `1.1 范围` 被当成多级编号标题）。

这条规则本身是对的，但它与 2.2 的塌词、以及「整页目录被识别成表格」叠加后形成**连锁**：目录页 → 判为表格 → 每行 `ln.row=True` → 标题晋升被封锁 → `第一章 总则` 既不成标题、又因空格被删而字面失真 → 三条 `contains` 全缺。

**根因归纳**：三个各自合理的局部规则（间隙聚类成表、表格行不当标题、空白字符不入聚类）**叠加后产生全局损伤，而没有任何一层看得见这个叠加**。这是本轮最值得记的架构级观察：缺陷不在任何单个函数里，在函数之间的假设不兼容。

### 3.3 B-47：门禁判据只在非默认档生效

`hard_10_cid_proxy.pdf` 期望 `reject:E4221`，实际转换成功。S1.5 的 `noise>0.95 且 letters/chars<0.05` 判据只在 `even5`/`legacy3` 档生效（与 B-32 同根：`GateCollector.finish()` 只在 `mode != "auto"` 分支读该键），CID 代理未必落进该区间。

记缺口不记缺陷，因为**两种解释都成立**（阈值过松 vs 夹具构造意图失真），区分二者需真实无 `/ToUnicode` 样本。

### 3.4 分片面：等价性已证，产品内并行仍未实施

`ops/bench/opt6_shard_equivalence.py` 本轮复跑 exit 0：320 页金样本按 1/2/3/4 段切分后重拼，段数档全部 **5789 块**、正文 **1775484 B** 等价、结构（剥豁免）等价，seams 0/1/2/3、dedupe 0/30/65/107；D2 负夹具证明「各片自取众数」确实会与整篇众数分叉（全局 12.0 vs 各段 `[12.0, 7.0]`），D3 钉住门禁页行 `[158]` vs 切段行 `[172]`，D4 证明家具窗口按「片尾 2 页重叠」切分时块数与整篇一致（1883/1883，0 处不齐）。

B-38 第一步（先证等价）**已达成**；第二步（产品内实施并行）仍只登记——本机只能证等价性，不能证多进程池在低配机上的收益与稳定性，且 `PIPELINE_VERSION` 升位要与黄金重烤同批。这是**性能优先级最高**的开放项（实测杠杆 2.79×）。

## 4. 生成层（S4 / 打包）

### 4.1 本层实测全绿，但绿的方式值得警惕

M6 十项全通过：12 键 front-matter 契约（对 `PIPELINE_VERSION`/`SCHEMA_VERSION` 双常量）、注入面四条断言、`report.html` 转义、代码围栏成对、CJK/拉丁保真、三次幂等（正文 + 块类型序列）、`preserve_marks_strike` 双档（off 无 `~~` / on 有）、无静默截断（字符比落在 0.8–1.25 带内）。

**警惕点在 O-b**：TC-M8-04 首稿检查 zip 里的 `meta.json` 是否泄漏内部锚，而 `meta.json` 在该 zip 里根本不存在（条目只有 `content.md`/`ir.json`/`report.html`）。前件恒假 ⇒ 断言恒真 ⇒ 无论产品怎么改都 PASS。这是第三轮 O-g 的同型再现，说明**「红线是标记字符串检查、不是结构回读」这一根因没有随着上一轮登记而消失**。

**修复形态值得推广**：改后的断言自带**非恒真证明**——交付面命中数必须为 0，**且** `ir.json` 命中数必须 > 0（实测 1120）。后一个数不是断言目标，是「这条断言确实有牙齿」的证据。凡「某物不得出现」型红线，都应配一条「同一检查在应当命中的地方确实命中」的正夹具。

### 4.2 注入面口径的更正（O-a）

首稿断言「产物中不得出现 `javascript:` 字样」是**错的口径**。实测产物 `\[click\](javascript:alert(3))`——`]` 已转义，Markdown 不生成锚，渲染后不可执行也不可点击；把这串字抹掉才是内容损失（源文档确实写了它）。

正确口径是「**渲染后不可执行 / 不可点击**」，落成四条并列断言：无原样 `<script>`、无未转义的 `](javascript:` 活链接、`report.html` 无 `href="javascript:`、无 `<script>alert(`。

**根因**：安全红线容易写成「敏感字符串黑名单」，而黑名单与「保真交付源文本」这条承诺**天然冲突**。凡安全断言，判据必须落在**渲染后的可行为性**上，不能落在字符出现与否上。

### 4.3 产物字节冻结：既是防线也是改进税

本轮有两项修复被这条税挡住：**B-44 的空格保真半**（2.2）与 **B-37 转义单一来源**。两者都不需要人工裁定，改法明确，但都会动产物字节，因此必须与 22 篇语料黄金重烤同批，而重烤需要人工逐篇复核。

这是**设计上的自觉取舍**（冻结让「等价性证明」成为可能，B-38 的第一步正建立在此之上），但代价是：一类「改法已知、只差批次」的缺陷会长期停在登记状态。第 5 节 OPT4-8 提议把重烤做成**可批量复核的 diff 报告**，把人工成本从「逐篇读产物」降到「逐条读 diff」。

## 5. 校验 / 契约 / 度量层

### 5.1 C-1..C-6：文档承诺不由实测回读

六项文档精度偏差（详见《对照表》第 4 节）的共同根因是**同一条**：附录 C 的契约表由设计意图写出，从来没有一条自动检查把它与实际响应体对账。

最典型的 C-1：附录 C 的 `POST /jobs` 一行里，**成功列已写「逐文件状态可为 `conflict`」，错误列又写「409 `E4091`」**——同一行自相矛盾，而实测 HTTP 409 在整个 API 面不可达（E4091 两条抛出路径都被就地捕获折进 202；E4092 只作为作业码字符串出现在 `worker.py`，从不作为 `ApiError` 抛出）。

**为什么这类偏差危险**：调用方按 409 写重试逻辑，会留一段永不执行的分支，同时漏掉真实需要处理的 202/`conflict`。它不影响本机测试全绿，只在集成时爆。

**可落地的红线形态**（本轮未实施，见 OPT4-5）：把附录 C 的成功列/错误列解析成「(端点, 方法) → 声明的状态码集合」，与一次实测扫描得到的**实际可达状态码集合**做双向差。`tests/test_ch491_doc_sync.py` 已有同型机制（解析文档锚点 → 与代码对账 → 锚点解析失败即报「红线锚点失效」而非跳过），可直接复用其骨架。

### 5.3 真值面：自证循环仍是头号缺陷

- `tests/corpus/expected/*.md` 是**重烤基线**——只防漂移，不判对错。
- `tests/corpus/ideal/` 21 份标注是**程序化真值**（DOCX=XML 样式、PDF=生成器字号），`run_metrics.py` 实测 DOCX 111/111 标题 micro 召回 1.0、PDF 102/102 1.0、漂移 F1 全 1.0——但这些 1.0 只证明「与程序化真值一致」。B-34 的登记里已明写：把它接进门禁等于**把自证循环写成红线**。
- `tests/corpus/hard/` 是**唯一独立真值面**（真值来自生成器声明的构造意图），本轮 6/10，且是两项发布阻断缺陷的唯一来源。
- `tests/corpus/real/` 恒 `not_run`（`work/real_samples` 为空），B-49 是它的人工侧。

**度量结论**：`tests/qa/evaluate.py` 宏观指标本轮全项不变（heading_f1 1.0、table_teds 0.9874、structure_bsf 1.0、order_nid 1.0、**honest 1.0**、21 ok / 1 rejected / 0 error）；`tests/qa/trace.py` 双向追溯 COVERAGE FR=0.4643 / NFR=0.8182 / W=1.0 / E=1.0，孤儿 0，未覆盖 FR_other 15 / NFR 2；`tests/qa/defect_scan.py` blocking 0 / **major 2（`duplicate_anchor`）** / minor 2（`fence_no_lang`）。

其中 major 2（`duplicate_anchor`）与 minor 2（`fence_no_lang`）**全部在 `tests/qa/defect_scan.py::CORPUS_KNOWN_BENIGN` 里逐 (样本, 规则) 登记**：`pdf_08_large_40p` 与 `docx_08_large_30sections` 各 1 条重复锚点，成因是语料生成器循环输出同名二级标题 `1.1 章节说明`（语料设计，不是缺陷）；`pdf_04_links_code_2p` 与 `docx_07_code_quote` 各 1 条无语言标注围栏，成因是生成器特意造的 MD040 展示样本（源侧本就没有语言标注）。该表注释明写「重复标题**不是** TOC 缓存被当正文（D09 的真实形态）」——**因此这 2 条 major 不能作为 B-48 的证据**，本册首稿曾如此误引，已更正。

**B-48（D09 目录域缓存结果重复输出）仍开放**，正确证据是 `tests/qa/test_hard_gate.py::test_hard_expectations_structure[D09]` 以 `xfail(strict)` 挂着，reason 原文 `B-48 未闭合`（本轮实测 `-rxX` 输出：D02/D05/D08/D09/D10 五条全 XFAIL，无 XPASS）。

而 D09 在**难度腿上是 PASS** 的（TC-HD-09：`九、目录域测试` H1、三条章节标题均 H1、`contains` 命中）。同一份样本在两条腿上给出相反结论，原因是**两条腿看的面不同**：`run_hard.py` 只核对 `expectations.json` 声明的 `contains`/`headings` 字段，`test_hard_gate` 核对的是结构面（不得重复标题）。声明面绿、结构面红——这正是第三轮 O-g「断言面窄于声明面」的又一次显形，也是 B-46（难度腿入门禁，切换点是 `test_hard_gate.GATE_READY`）必须存在的原因：**只要结构面还挂在 xfail 上，「难度语料全绿」这句话就不成立。**

`FR=0.4643` 是本层最刺眼的数：需求面覆盖率不足一半，未覆盖的 15 项全在 FR_other。它的分母是文档里的功能需求条目，分子是有用例双向追溯到的条目——**这个数低不代表功能没实现，代表实现没有被追溯到需求**。B-46（难度腿入门禁）与 B-34（指标入门禁）都排在这条之后，因为没有追溯面，入门禁的红线也无法证明覆盖了需求。

### 5.4 覆盖率与门禁预算

- 语句覆盖率：`TOTAL 7843 stmts / 737 miss` → 打出 **91%**、精确 **90.60%**（O-h 纪律：双写）。距 92% 目标 1.4 个百分点。
- 单点低覆盖：`doc2md/security/perms.py` **40%**（75 stmts / 45 miss）——安全面覆盖率最低的一处，且它决定权限边界。`worker.py` 85%（376/55）、`storage/db.py` 96%、`repo.py` 97%、`fts.py` 98%。
- 门禁 683 passed / 0 skipped；全量 1516 收集 = 1500 passed / 0 failed / 10 skipped / 6 xfailed。16 条 skip/xfail 全部是既有显形缺口（2 Windows junction 平台门 + 难度骨架 TODO-skip/xfail），非新增。
- `tests/qa/realtest.py` 编排器：**overall=pass**，L1=683/0/0/0，L2=1516/0/0/16，NOTRUN=2（`L4_install/clean_venv_install`、`L5_quality/real_leg`）。

`perms.py` 的 40% 是**唯一一个「低覆盖率 + 高影响面」重合**的模块。它没进本轮缺陷清单，因为没有实测到错误行为；但按「静默失效是第一类缺陷」的口径，一个决定权限边界的模块有 45 条语句从未被任何测试执行过，本身就是待办（OPT4-11）。
