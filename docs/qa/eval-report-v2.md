## 4. 偏差量化与根因

### V-01 合并单元格拍平 → TEDS 固定 0.911 【中 · 已知取舍】

- **量化**：`docx_03` 0.9127 / `docx_10` 0.9118 / `docx_11` 0.9110。**凡源端 `merged_cells > 0` 的表一律 0.911，无合并的表一律 1.000**——归因干净，无其他混杂。
- **根因**：GFM 管道表无 `colspan` 语义；§1.2 非目标 6 明确「DOCX 侧 `gridSpan` 不还原为 GFM 跨列语法」。
- **性质**：**已知取舍，不是缺陷**。取舍结果已由 W1045 + 报告顶部提示 + API 透出（O-05）显式暴露，本轮 `HONEST = 1.0` 证实降级留痕生效。
- **建议**：不改行为，改**可发现性**——把「本表含合并单元格，已拍平」写进产物表格前的提示行，而非只在 IR/API 层留痕。

### V-02 代码块无语言标记 → MD040 【中 · 真缺陷】

- **量化**：2/21 样本（9.5%）命中，`lint_contract` 0.375 / 0.167。
- **根因**：S3 判定代码块时未携带语言信息；S4 渲染围栏不补 lang。离线约束下**无法推断语言**（需模型或启发式），但参考资料给的兜底是明确的：

  > 代码块必须有语言标记，无高亮写 `text`，**绝不裸 fence**。

- **建议**：S4 对无 lang 的围栏补 `text`。这是纯渲染层改动、确定性、零依赖，成本极低——但要按 G6 走全语料重烤（会改产物字节）。

### V-03 跨页表格裂表 + 丢列 + 无告警 【高 · 真缺陷】

- **量化**：期望 1 张 41×3，实际 2 张（**2 列** 37 行 + 3 列 5 行）。第 1 张**丢掉「金额」列**；`warnings` 为**空**。
- **根因链**：
  1. S3 表格行由字符横向间隙推断，跨页后列位置基准变化 → 列聚类结果不一致；
  2. 跨页边界无「续表」判定 → 一张表裂成两张；
  3. **裂表与丢列都没进 warnings** → 静默降级（C-29 同源病灶）。
- **性质**：这是本轮**唯一的「数据失真」级缺陷**——丢列意味着数字与科目的对应关系可能错位，比串位更危险。
- **建议**：见 §5 P0-1。

### V-04 点线引导符误判为表格 + 空格丢失 【中高 · 真缺陷】

- **量化**：目录 3 条目被判为 3 行 × 3 列表格；单元格内容为 `['第一章总则', '....................', '1']`——**两处错**：① 「第一章 总则」的空格丢失；② 引导符 `......` 成为真实单元格内容。
- **根因**：
  1. 空格丢失与 **C-04（折行空白保真）同源**——O-01 已修折线落在中西文空格的情形，但**引导符行内的列间空格**（靠 x 坐标分隔、无字符空白）仍无几何证据；
  2. 引导符行满足「行内含多个横向间隙簇」的表格判定条件 → 误判。
- **性质**：参考资料把「点线引导符 `......` 变成真实字符」单列为 PDF 表格的典型隐蔽错误。此处还叠加了把目录误判成表格。
- **建议**：见 §5 P0-2。

### V-05 加密 PDF 缺 `password_required` 诊断 【中 · 契约偏差】

**⚠ 第十八轮改判（CH-503，2026-10-25）：本条作废，D07 不构成偏差。** 原文照抄保留，
便于日后核对「报告写过的观测在什么条件下不再成立」。复现口径（本机 `.venv`，两个面都测）：

```
.venv/bin/python -m doc2md.cli convert tests/corpus/hard/hard_07_encrypted.pdf --out /tmp/h7
# {"status":"error","code":"E4151", … ,"detail":{"file":"hard_07_encrypted.pdf",
#  "exc":"PdfminerException","password_required":true}}
```

管线面直调 `convert()` 得到同一份 detail；钉住它的红线是
`tests/test_ch492_fixes.py::test_encrypted_pdf_detail_has_password_required` 与
`…::test_truncated_pdf_detail_has_no_password_flag`（后者断言的是**键不存在**，不是
`false`——§5 P1-1 的出口判据 ② 原写成「损坏 PDF 仍为 `false`」，与产品形态不符，
本轮一并改正）。判定链上没有任何一处能把 `password_required` 吞掉，所以本条不是
「已修好所以过时」，而是**当时的观测本身与 2.18.0 的代码不符**：登记矛盾按
「以可复现的实测为准」收口，不再留待办。

- **量化**：`E4151` 拒收正确，但 `detail = {'file': ...}`，无 `password_required`。
- **影响**：README / CH-492 声称「`_pdf_tail_has_encrypt` 尾窗探测，口令加密与结构损坏可区分」。实测该 flag **未透出到异常 detail**，用户拿到 E4151 无法判断是「要口令」还是「文件坏了」——契约 §5.2「用户按码可知下一步动作」未完全兑现。
- **建议**：见 §5 P1-1。

## 6. 本轮方法论修正（记录，避免重犯）

评测过程中发现并修正了三处**度量方法本身的错误**。它们都曾让分数虚低，若未修正会被误当成产品缺陷：

| 问题 | 修正前 | 修正后 |
|---|---|---|
| 参照骨架按「先标题后表格」分类排列，丢失文档真实顺序 | `order_nid` 0.9099（docx_11 仅 0.27） | **1.0000** |
| 真值与预测皆为空时判 0 分 | pdf_10 `heading_f1` / `bsf` = 0.0 | **1.0000**（与 `char_f1` 同口径：皆空=完美） |
| `ideal/` 空真值被源端字号启发式覆盖 | pdf_10 栏头被捞回成标题 | 以 `ideal/` 为权威，启发式不再覆盖 |

**教训**：分数异常低时，先怀疑参照系，再怀疑产品。本轮 0.09 的 NID 差、1 个样本的满分差，全部是度量方法的错，不是管线的错。
